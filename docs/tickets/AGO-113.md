## Overview
"As a member, I want to type or attach a goal so that the Manager can turn it into tasks."

Acceptance criteria (verbatim):
1. Submitting a goal creates a goal record and a Manager task
2. Empty goals are rejected
3. Tests pass, no regressions, PR reviewed and merged, docs updated (see Definition of Done)

## What exists today (explored 2026-11-20)
- `public.tasks` (AGO-74): `title` (1..300), `description`, `status`, `agent_id` (assignee, composite FK to `agents`), `created_by` (member), `department_id` (AGO-96). RLS (AGO-107): select viewer, insert/update/delete member, `created_by` pinned to the caller's member id. Insert grant covers `workspace_id, title, description, status, agent_id, created_by`.
- There is no goals table and no goal inbox code. There is no "Manager" marker in the schema: an agent's `role` is free text set in the wizard (AGO-141), and the shared template `manager` (`packages/shared/src/agents/agent-templates.ts`) creates an agent with `role = "Manager"`. So "the Manager" in a workspace = an active (not archived) agent whose role is `Manager`, compared case-insensitively.
- Pattern for an atomic multi-row write: `create_agent` (AGO-141) is a `plpgsql` RPC with `set search_path = ''`, an explicit `private.is_member(...)` check, `private.current_member_id(...)` for attribution, execute granted to `authenticated` only.
- Human-only: `requireHumanRequest` / `AgentCredentialRejectedError` (`apps/web/src/lib/auth/human-only.ts`), used by every action in `features/agents/actions.ts`.
- Forms: `useActionState` plus a server action, native `<textarea>`/`<Input>`/`<Button>` from `@ago/ui`, errors with `role="alert"`. React Hook Form is **not** installed in the repo.
- Routes: signed-in pages live under `apps/web/src/app/app/*` (thin; `getCurrentUser` + `getActiveWorkspace`).

## Design
**Database** (one migration `supabase/migrations/<ts>_ago_113_goals.sql` plus `supabase/rollbacks/<ts>_ago_113_goals.down.sql`; additive):
- `public.goals`: `id`, `workspace_id` (FK, cascade), `text text not null`, `created_by uuid not null` (composite FK to `members`), `created_at`. `unique (workspace_id, id)`.
  - CHECK: `char_length(text) between 1 and 5000` **and** the text contains at least one character that is not whitespace or zero-width (`text !~ '^[\s ​-‍⁠﻿]*$'`). So neither the API nor a direct insert can store an empty or invisible goal.
  - RLS on; select for any workspace member (viewer and up); **no** insert/update/delete grant to `authenticated` (a goal is immutable and is created only through the RPC, so a goal can never exist without its Manager task).
- `public.tasks.goal_id uuid` nullable, composite FK `(workspace_id, goal_id)` to `goals` (`on delete set null (goal_id)`), index. In no column grant: only the RPC sets it.
- `public.submit_goal(p_workspace_id uuid, p_text text) returns uuid` (returns the goal id): one transaction. Checks the caller is a `member` or `owner` (not a viewer), validates the text, finds the Manager (oldest active agent with `lower(role) = 'manager'`), inserts the goal (`created_by = private.current_member_id`) and the task (title `Plan goal: <first 80 chars>`, description a fixed pointer saying the goal text is untrusted data in the linked goal, `agent_id` = the Manager, `goal_id`). Errors with stable codes: `42501` not a member, `22023` empty or too long, `P0002` no Manager. `SECURITY DEFINER`, `search_path = ''`, execute for `authenticated` only (see Decision 3).
- Rollback: drops the function, the column and the table. Local only, same style as AGO-194.

**Shared** (`packages/shared/src/goals/`, additive, barrel export): `submitGoalSchema` (strict, `workspaceId` uuid + `text`), `normalizeGoalText` (CRLF to LF, strip zero-width, trim), `GOAL_TEXT_MAX_LENGTH = 5000`, messages. A zod-free `goal-limits.ts` for the client, as `agent-limits.ts` does.

**Web** (`apps/web/src/features/work/`): `GoalInboxForm.tsx` (textarea, live character count, inline error `role="alert"`, `aria-invalid`, disabled while pending, resets on success), `actions.ts` (`submitGoalAction`: `requireHumanRequest` first, `parseInput`, calls the data layer, maps errors to messages), `goal-inbox.ts` (data access: `requireWorkspaceRole(..., "member")`, `supabase.rpc("submit_goal")`, list recent goals), a goal list (text shown as plain text, never as markup). Route `apps/web/src/app/app/goals/page.tsx` (thin). Viewers see the list but not the form.

**Security**: workspace_id scoping and RLS on `goals`; agent credentials are refused on the action (AGO-148 pattern) and the RPC needs a human session (`auth.uid()`); goal text is stored as-is, rendered as text and never interpreted; the task description for the Manager does not embed the goal text. No model calls.

## Boundaries
- **Always:** scope by `workspace_id`; validate with Zod at the boundary and again in the DB; human-only; text is untrusted data.
- **Ask first:** new dependencies (RHF), attachments.
- **Never:** let an agent credential submit a goal; interpret goal text; edit existing migrations.

## API changes
None (server action only). New RPC `public.submit_goal`.

## Database changes
New table `goals` (RLS), nullable `tasks.goal_id`, RPC `submit_goal`. Reversible via the rollback file.

## Dependencies on other tickets
AGO-82, AGO-115 (done). AGO-117 reads `goals` and the linked task.

## Known limitations
Text only; goals are immutable and cannot be edited or deleted yet; the list shows the latest 50.

## Testing notes
Unit: shared schema (empty, whitespace, zero-width, too long), action mapping, form. pgTAP (under the db lock): constraint, RLS cross-workspace denial, viewer refused, no direct insert, RPC atomicity (no Manager rolls back the goal), attribution. Component test for the inline error.

## As built (2026-11-20)
- Matches the design. Files: migration `20261120010001_ago_113_goals.sql` and its rollback; `packages/shared/src/goals/` (zod-free `goal-limits.ts`, `goal-schemas.ts`, a `./goal-limits` export for the client); `apps/web/src/features/work/` (`goal-inbox.ts`, `submit-goal.ts`, `actions.ts`, `GoalInboxForm.tsx`, `GoalList.tsx`); route `/app/goals`.
- Supabase default privileges open every new public table to anon, authenticated and service_role, so the migration revokes all on `goals` and grants select back. The same is done for `submit_goal` (execute for `authenticated` only).
- Text rules live in three places that are kept in step: the client form, the Zod schema, and the SQL (CHECK constraints plus the RPC). Stored text is normalised (CRLF to LF, zero-width characters removed, trimmed); blank or over 5000 characters is refused.
- Existing catalog pgTAP tests were edited for the new table (counts and lists only): `core_schema`, `core_schema_qa`, `rls_catalog`, `rls_every_table`, `rls_every_table_qa`. New `goal_inbox.test.sql` (about 53 assertions).
- The rollback file was written but not executed.
- Deviations: no React Hook Form (Decision 4); `SECURITY DEFINER` (Decision 3).
