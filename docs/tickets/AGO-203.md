# AGO-203 - Make free-port.mjs detect ports held on 127.0.0.1 on Windows

## Overview
Bug, wave 2. `scripts/free-port.mjs` only probed `0.0.0.0`, which on Windows still succeeds while another process listens on `127.0.0.1`, so parallel worktrees collided (seen on 3100 and 3600). Jira: https://stratyge.atlassian.net/browse/AGO-203

## Implementation details
- A port is free only if it binds on `127.0.0.1`, `0.0.0.0` and `::1`, checked in that order.
- `::1` is skipped when the bind fails with `EADDRNOTAVAIL`, `EAFNOSUPPORT` or `EPROTONOSUPPORT` (no IPv6 loopback). Any other error, including `EADDRINUSE` and `EACCES`, marks the port as taken.
- CLI contract unchanged: one optional start argument (default 3100), 200 tries, prints one port, exit 1 when none is found.
- `scripts/free-port.test.mjs` runs the CLI as a subprocess against real listeners on each of the three addresses. The ::1 case skips when IPv6 is unavailable.

### Decisions taken
- Probe all three addresses sequentially (recommended): simple, and short-circuits on the first taken address.
- Test through the CLI rather than exporting functions (recommended): keeps the script a plain CLI and tests the real contract.
- No docs change: usage is unchanged, so `docs/ai-workflow.md` is left alone.

## Known limitations
Only TCP loopback and wildcard IPv4/IPv6 `::1` are probed. There is a small race between the probe and the dev server binding the port.
