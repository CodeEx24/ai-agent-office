# AGO-167 - Implement the agent tool loop

## Overview
Jira: [AGO-167](https://stratyge.atlassian.net/browse/AGO-167) (US-034), epic EP-02, wave 2 (Agent Runtime + Guardrails).
Risk tier: high (AI-safety surface: policy, approvals, credentials).

Adds the loop that runs one agent run: build context -> call the model -> for each tool call, policy check ->
(execute | deny | stop for approval) -> feed the result back, until the model answers or a limit is hit.
Blocked-by AGO-151 (queue), AGO-145 (context builder) and AGO-164 (event emitter) are all Done.

Acceptance criteria and where they are proven:

| AC | Proof |
|---|---|
| Given a task, when run, then the loop ends with a result or a limit event | `agent-loop.test.ts` "result path" and "limits" (steps, tokens, wall time, hung model call); `agent-loop.integration.test.ts` result and step-limit runs through the real queue and database |
| Every tool call passes through the policy hook before execution | `agent-loop.test.ts` "every tool call passes the policy hook" (denied never runs, default deny, hook runs once before each execute, hook error or malformed answer is a deny, unknown tool, registry fixed after creation) and "approvals stop the step"; `policy-hook.test.ts`; integration deny and approval runs |
| Model credentials never appear in prompts or events | `agent-loop.test.ts` "credentials never leak" (fake key scanned across every event, log line and request body; error path with a key in the API error body); `claude-provider.test.ts` (key only in the `x-api-key` header) |
| Tests pass, no regressions, docs updated | `pnpm lint && pnpm typecheck && pnpm test`, this file |

## Implementation details
New module `apps/worker/src/agent/`:

- `model-provider.ts` - `ModelProvider` interface (`complete(request) -> text, toolCalls, usage`). The model is behind it.
- `claude-provider.ts` - the real provider: the plain Messages API tool loop over `fetch` (no new dependency).
  The key lives in its closure and goes only into the `x-api-key` header. **Never called by tests or CI.**
- `policy-hook.ts` - `PolicyHook.check(toolCall, context) -> allow | deny | needs_approval`, plus the default
  deny-by-default hook with a tier-0 allowlist (`get_current_time`). AGO-34 replaces it.
- `tools.ts` - `AgentTool`, a `ToolRegistry` fixed at creation, and the one built-in tier-0 tool.
- `agent-loop.ts` - `createAgentLoop(deps)` returns a `RunExecutor`, the seam AGO-151 left for this ticket.
- `wire.ts` - production wiring (real provider, Postgres context source, deny-by-default hook). Returns nothing when
  `ANTHROPIC_API_KEY` is unset, which keeps the old "queue accepts, nothing consumes" behavior.

Changes to existing code:

- `queue/run-processor.ts` - `RunOutcome.end` (`completed` | `limit_reached` | `paused`) and `NonRetryableRunError`.
  `limit_reached`: run marked `failed`, no `run.completed` (the limit event is the terminal event). `paused`: emits
  `run.paused`, run marked `paused`. A non-retryable error fails the run at once with its reason and spends no retries.
- `queue/run-store.ts` - `markPaused` and `RUN_STATUS.paused` (`runs.status` is free text, so no schema change).
- `context/context-builder.ts`, `context/pg-context-sources.ts` - an archived agent is refused (`agent_archived`).
- `config.ts` - `AGENT_MODEL`, `AGENT_MAX_STEPS` (25), `AGENT_MAX_TOKENS` (200000), `AGENT_MAX_WALL_MS` (600000,
  under the 900 s job expiry), `CONTEXT_MAX_CHARS` (wired into the builder).
- `packages/shared/src/events/run-events.ts` - new event `context.cut` (counts and source labels only). The AGO-164
  v1 list test and acceptance script were updated from 24 to 25 types.
- `main.ts` - builds the production executor when a key exists and no executor is injected; closes its pool on stop.

How the guarantees hold:

- **No bypass:** `executeToolCall` is the only function that calls `tool.execute`, and it calls the hook first. The registry
  has no `register`, so a tool cannot appear mid-run. An unregistered tool is shown to the hook as tier 4 and is denied
  even if a hook says allow.
- **Fail closed:** a hook that throws, or returns a malformed decision, is a deny. Tier 3 and 4 tools never run on `allow`
  (AGO-125): the call becomes `needs_approval`.
- **Approvals:** `needs_approval` emits `approval.requested` (`payload_hash` = sha256 of the canonical tool name + input,
  24 h expiry, so a timeout is a deny), never executes, and ends the run `paused`. Resume is AGO-30.
- **Limits:** steps, tokens and wall time are checked before every model call; a model call that outlives the wall-time
  limit is aborted; tokens are also checked after a response, before any tool runs. Each emits `run.limit_reached`.
- **Context:** tool results go back through the context builder as untrusted retrieved data, each cut to 20,000 characters
  (the builder throws over 100,000) with a `context.cut` event; the history is windowed to half the context cap, oldest first.
- **Credentials:** read once in `wire.ts` from the AGO-70 env, handed to the provider, nowhere else. Events carry hashes
  and counts, tool output is run through `scrubString` before it is stored or returned to the model, provider errors are
  scrubbed and bounded.

### Decisions taken (no human at the keyboard; recommended option picked)

| Decision | Chosen (recommended) | Why |
|---|---|---|
| Claude Agent SDK vs plain Messages API loop | Plain Messages API loop over `fetch` | The Agent SDK runs its own tool loop and permissions, which would put tool execution outside our policy hook. Also no new dependency (locked stack). |
| How tool results reach the model | Rebuild the context each step with results as untrusted `retrieved` items (no assistant/tool message history) | Keeps the trust model of AGO-145 (all tool output is untrusted data in the user message) and its size cap; the model is told each call's tool, input and result. |
| Default policy until AGO-34 | Deny by default; allow only the tier-0 allowlist `get_current_time` | Human in the loop; nothing without an explicit rule can run. |
| What `needs_approval` does | Stop the step, emit `approval.requested`, pause the run | There is no resume yet (AGO-30); the run must not continue or execute. |
| Run status when a limit is hit | `failed`, with `run.limit_reached` as the terminal event and no `run.completed` | A run with no result must not read as succeeded. |
| Event for cut context | New `context.cut` event type | AGO-145 carry-over asked for an event and no AGO-164 type fits; the schema header says to add one entry. |
| Archived agent | Builder throws `agent_archived`; the processor fails the run at once (no retries) | A retry cannot fix it. Fixes the AGO-145 carry-over without changing queries. |
| Schema slot | No migration | Everything fits existing tables; `runs.status` is free text. AGO-141 holds the schema slot. |

## API changes
None. Worker-internal. New optional worker env vars listed above.

## Database changes
None. No migration. Run status `paused` is a new value of the free-text `runs.status`.

## Dependencies on other tickets
- AGO-151: the loop is the `RunExecutor` the queue calls; idempotency per run is the queue's claim.
- AGO-145: `ContextBuilder.build(runId, { retrieved })`; its three carry-overs are done here.
- AGO-164: all events go through `RunEventEmitter`.
- AGO-104: failures reach Sentry through the processor with `run_id`; messages are scrubbed.
- AGO-125: tier 3+ is never automatic.
- AGO-34 (later): replaces the default policy hook. AGO-30 (later): resume after approval. AGO-166 (later): loop detection.

## Known limitations
- **No live model call was made** (money rule). The real Claude provider is covered by fake-`fetch` tests only. A live
  check against the Anthropic API needs the owner's explicit OK and is pending.
- Only one built-in tool (`get_current_time`); vault and other tools come with their tickets.
- Tool calls run one at a time; at most 8 per step.
- A paused run has no resume path until AGO-30. An approval nobody decides has an `expires_at`, but nothing writes the
  expiry decision yet (AGO-30 and the approvals tickets). The tool is not executed either way.
- The model sees the history as untrusted text, not as native tool_use/tool_result turns; fine for now, revisit if quality needs it.
- `ModelProviderError.isRetryable` is not yet read by the loop: every provider error is thrown and the queue's retry policy applies.
