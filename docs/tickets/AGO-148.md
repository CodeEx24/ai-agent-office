# AGO-148 - Issue per-agent identity and short-lived scoped credentials

## Overview

Jira: AGO-148 (US-027), Epic EP-17 (Identity), Wave 2 (Agent Runtime + Guardrails), WS-E Security & Governance. Risk tier: **high** (identity, credentials, auth surface, new tables).

Give each agent its own identity and issue credentials per task that expire and are scoped to granted capabilities.

Acceptance criteria (verbatim from the ticket):

1. Credentials expire at task end or in 15 minutes, whichever is sooner
2. A credential cannot be used for a capability the agent lacks
3. Every issuance is logged
4. Tests pass, no regressions, PR reviewed and merged, docs updated (see Definition of Done)

Blocked by AGO-74 (core schema), AGO-151 (pg-boss queue), AGO-125 (capability catalog): all Done.

## Implementation details

| Piece | Where | Role |
|---|---|---|
| Identity and issuance log | `supabase/migrations/20261107130001_ago_148_agent_identity_credentials.sql` | `agent_identities` (one non-login principal per agent), `agent_credentials` (append-only issuance log), triggers for issue checks, append-only, revoke on run end |
| Claims, expiry, intersection | `packages/shared/src/identity/credential-schemas.ts` | `computeCredentialExpiry` (min of task end and now + 15 min), `intersectCapabilities`, claims schema, `hasAgentCredential`; no `node:crypto`, safe for the web app |
| Signing secret | `packages/shared/src/env/schema.ts` | `AGENT_CREDENTIAL_SIGNING_SECRET`: server-only, 32+ chars, required when deployed, dev-only fallback locally |
| Token codec | `apps/worker/src/identity/credential-token.ts` | HS256 token `ago_agt_<header>.<payload>.<signature>` with `node:crypto` (no new dependency), constant-time compare, sha256 hash |
| Store | `apps/worker/src/identity/credential-store.ts` | `CredentialStore` interface + Postgres implementation |
| Issuer + verifier | `apps/worker/src/identity/credential-service.ts` | `createCredentialIssuer`, `createCredentialVerifier`: the seam AGO-167's loop will use |
| Human-only guard | `apps/web/src/lib/auth/human-only.ts` | proxy, capabilities route and create-agent action refuse an agent credential |
| Redaction | `packages/shared/src/redaction/redact.ts` | `ago_agt_...` added to `SECRET_VALUE_PATTERNS` (logs, Sentry, client bundle check) |

Flow: the worker (via AGO-167's loop, through the `CredentialIssuer` interface) asks for a credential for a run. The issuer reads the agent's granted, catalog-enabled capabilities, intersects them with the request, computes the expiry, signs the claims, and appends one row (hash only). A tool call presents the token to the verifier, which checks signature, expiry, the stored row (not revoked, same workspace, agent, run) and that the capability is on both the token and the row. The result always says `policyCheckRequired: true`: a credential only proves the agent holds a capability; the policy engine and human approvals (tier 3+) are unchanged.

Patterns reused: AGO-128/AGO-102 append-only trigger pattern (including the TRUNCATE statement trigger and ENABLE ALWAYS), AGO-107 per-command RLS and exact grants, AGO-164 pg store style, AGO-70 env schema, AGO-104 redaction list, existing `capabilityKeySchema`.

## API changes

No new endpoint. Behavior change: any request carrying `Authorization: Bearer ago_agt_...` gets **403** `{"error":"agent_credential_not_allowed"}` from the proxy (every route; the agent allow-list `AGENT_ALLOWED_PATH_PREFIXES` is empty), and again from `GET /api/capabilities` and `createAgentAction` (defense in depth). It is refused even when a session cookie is also present.

## Database changes

Migration `20261107130001_ago_148_agent_identity_credentials.sql`; rollback `supabase/rollbacks/20261107130001_ago_148_agent_identity_credentials.down.sql` (proved by `scripts/ago-148-rollback.test.mjs`: roll back, re-apply, empty schema diff).

- `agent_identities(id, workspace_id, agent_id, created_at)`: unique per agent, created by an AFTER INSERT trigger on `agents` (and backfilled). Never an auth user. Members read; nobody writes through the API.
- `agent_credentials(id, workspace_id, agent_id, run_id, token_hash, capabilities, issued_at, expires_at, revoked_at)`: `expires_at <= issued_at + 15 minutes` as a CHECK; BEFORE INSERT trigger rejects a run of another agent or workspace, a run that has ended, an `issued_at` more than 30 s from the database clock, and any capability the agent lacks (not granted, disabled or not in the catalog); append-only for every role (UPDATE, DELETE, TRUNCATE raise, ENABLE ALWAYS) except `revoked_at` null to a timestamp once; revoked by a trigger when the run leaves queued/running. Members and viewers read their own workspace's rows. `service_role` may insert and set `revoked_at` only.
- Existing catalog tests were updated for 18 tables (`rls_catalog`, `core_schema`, `core_schema_qa`, `rls_every_table`, `rls_every_table_qa`); `agent_credentials` stamps `issued_at` instead of `created_at`, and neither new table has `updated_at`.
- Types regenerated (`packages/shared/src/db/database.types.ts`).

## Decisions taken (no human at the keyboard: the recommended option was chosen)

| # | Decision | Chosen (recommended) | Alternative | Why |
|---|---|---|---|---|
| 1 | Token format | Signed HS256 token **and** a hash row in the log (verifier needs both) | Opaque random token with hash lookup only; or a JWT library | Uses the AGO-70 signing secret as the coordinator suggested, no new dependency (locked stack), cheap signature check before any DB read, and the row stays authoritative for revocation and scope (a leaked secret alone cannot mint a usable credential) |
| 2 | Identity | Own table `agent_identities`, one non-login principal per agent, created by trigger | Reuse `agents.id` only; or create an `auth.users` row | The ticket says each agent has its own identity; an auth user would be a login principal (a human-auth surface). `agents.id` stays the subject; the identity row is the explicit record |
| 3 | Where rules are enforced | Worker computes, **database re-checks** (CHECK + trigger) | Worker only | A buggy or compromised caller (even `service_role`) cannot issue a longer-lived or broader credential |
| 4 | Append-only vs `revoked_at` | Append-only with one exception: `revoked_at` null to a timestamp, once | Separate revocations table | One row per credential, simplest audit, still impossible to edit or delete anything else |
| 5 | Revocation on run end | Database trigger on `runs.status` **plus** `revokeForRun` in the issuer | Worker call only | Covers the kill switch, a crashed worker and a manually stopped run |
| 6 | Capability mismatch at issue time | Drop requested capabilities the agent lacks and report them (`droppedCapabilities`) | Fail the whole issuance | The credential is the intersection (AC2); the caller decides whether a dropped capability is fatal. The database still rejects a forced insert |
| 7 | "Task end" | Optional `taskEndsAt` on the issue request; a past end throws `TaskAlreadyEndedError`; the run ending revokes | Add a deadline column to tasks | Tasks have no end column and no ticket asks for one; the run is the unit of work. No schema change beyond the two tables |
| 8 | Human-only enforcement | Proxy (all routes, empty allow-list) + route + server action | Per-route only | A new route cannot forget the guard; the check is by token prefix, so it needs no crypto |
| 9 | Run events | Not added (the table is the log); the worker also logs one line per issuance without the token | New `credential.issued` run event | Keeps this ticket out of the event schema; follow-up |
| 10 | `.env.example` | Not edited (agents may not edit `.env*`); the coordinator was asked for the placeholder line | - | Brief constraint |
| 11 | Existing catalog tests | Updated counts and the `created_at`/`updated_at` rule | Special-case the new tables elsewhere | These tests are catalog-driven; the new tables are real tables |

## Known limitations

- AGO-167's loop is not wired to the issuer yet (it was not merged; interface only). Until it is, no credential is issued at runtime.
- A tool that is handed the token must send it only to internal tool endpoints; the allow-list for agent-callable HTTP routes is empty by design.
- Signing-secret rotation invalidates outstanding credentials (acceptable: at most 15 minutes).
- No run event is emitted per issuance (follow-up).
- Clock skew: `issued_at` comes from the worker and must be within 30 s of the database clock.
