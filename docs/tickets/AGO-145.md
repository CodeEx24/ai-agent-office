# AGO-145 - US-026 Build the context builder

## Overview
Epic EP-02 (Agent runtime), wave 2 (Agent Runtime + Guardrails), workstream WS-B, risk tier **high** (prompt-injection boundary, workspace isolation, AI safety). Jira: https://stratyge.atlassian.net/browse/AGO-145. Blocked by AGO-143 (worker skeleton) and AGO-128 (skill library), both done. Unblocks AGO-167 (tool loop), AGO-182 (vault map) and AGO-23 (mark retrieved content as untrusted).

"Assemble the agent prompt, task packet, assigned skills and a vault map for each run, marking retrieved content as data."

Acceptance criteria (verbatim):
- Context contains only skills assigned to the agent
- Retrieved text is wrapped and labeled as untrusted data
- Context size is capped and truncation is logged
- Tests pass, no regressions, PR reviewed and merged, docs updated (see Definition of Done)

No model is called in this ticket.

## Implementation details
Server-only code in `apps/worker/src/context/`, shapes in `packages/shared/src/context/`.

- `ContextBuilder.build(runId, { retrieved? }) -> { system, messages, metadata }` is the interface the tool loop (AGO-167) will call. `createContextBuilder({ source, vault?, logger, maxChars? })` builds it from three ports: `RunContextSource` (run, agent, task, assigned skills), `VaultMapProvider` (paths and titles only; the default is an empty stub because the vault is a later epic) and the AGO-143 logger.
- `createPgRunContextSource(db)` is the Postgres source. It takes any `{ query }` (a pool or one transaction client). The run row supplies `workspace_id`; every statement then names `workspace_id` and joins on the composite `(workspace_id, id)` keys.
- `untrusted.ts` is the single helper that builds `<untrusted_data source="...">` blocks. It NFKC-normalises content, escapes any `<` that could read as our opening or closing tag (any case, whitespace, `_`/`-`/space variants, zero-width and other format characters, fullwidth and small-form brackets), sanitises the `source` label to `[A-Za-z0-9:_./@-]`, and exports the system rule (`UNTRUSTED_DATA_RULES`). A truncated text never ends in a half tag (`stripPartialDelimiter`).
- Layout. `system` is trusted text only: platform rules (data-not-instructions, no self-approval, policy lives outside the prompt), the agent profile and **owner** skills. The single user message holds everything untrusted, each in its own labeled block: the task (title and description), **pack** skills, the vault map (paths and titles are attacker-controlled) and retrieved items.
- Size cap. `maxChars` (default `DEFAULT_CONTEXT_MAX_CHARS` = 48,000, about 12,000 tokens at 4 characters per token). Priority: platform rules + agent profile (never cut; if they alone exceed the cap `build` throws `ContextBuildError("budget_too_small")`) > task > skills > vault map > retrieved. Sections are placed in that order and measured as rendered, so the lowest priority is cut first, and once any section is cut nothing below it is kept. The task and a retrieved item are truncated (raw text first, then escaped and wrapped, so the closing tag is always present); skills are dropped whole, from the end of the `(name, id)` order; the vault map is cut at line boundaries.
- Logging. A cut is logged once at `warn` through the run-scoped logger (`run_id`, `agent_id`, `workspace_id`) with `budget_chars`, `used_chars` and `cuts[] = { section, source, action, original_chars, kept_chars, items_dropped }`. Never the cut text. The same `cuts` are returned in `metadata` so AGO-167 can emit an event.
- Output is deterministic: no clock or randomness, skills sorted by `(name, id)`, so the same inputs give the same string.

### Decisions taken (no human at the keyboard; recommended option chosen each time)
| Decision | Chosen | Why |
|---|---|---|
| Which skill version a run reads | The skill's latest (`skills.version` / `skills.body`); `{ id, name, version }` of each included skill is returned in `metadata.skills` | AGO-128 shipped assignments with no pin column ("follow latest"). Pinning needs a schema change, which this ticket does not hold the slot for. The metadata records exactly which version a run saw, and pinning is a follow-up. |
| Agent prompt and role | `AgentProfile { name, role, prompt }`; the Postgres source fills `role` from `agents.description` and `prompt` stays null | `agents` has neither column; the agent wizard (AGO-141) adds them. The interface is ready for them. |
| Owner skills trusted vs "skill text is untrusted" (AGO-128, `skills.body` comment) | Owner-written skills are trusted instructions in `system`; skills of origin `pack` are untrusted data in the user message | The brief and CLAUDE.md agent-pack rules: owners write skills through an owner-only path (AGO-128 RLS), packs are untrusted. The AGO-128 wording means "never treat skill text as a way to change platform rules", which still holds: skills never grant capabilities and the system rules say so. |
| Skill origin | Required `origin: "owner" \| "pack"` with no default in the schema. The Postgres source returns `owner` for every row | No origin column exists and no pack import exists yet, so every row today is owner-written. A required field means AGO-191 (pack import) cannot land a pack skill as trusted by omission; it must store the origin and this mapping must read it. |
| Task text | Untrusted, wrapped | Task descriptions can carry pasted external content. |
| Vault map | Wrapped as untrusted too | File names and titles are attacker-controlled. The vault is a later epic, so the provider is an empty stub behind an interface. |
| Source label | Sanitised to a fixed character set | A path such as `x"></untrusted_data>` would otherwise break out through the label, not the body. |
| Cut policy | Strict priority: once a section is cut, everything below it is dropped. Skills are dropped whole, in `(name, id)` order | "Cut lowest priority first" stays true and predictable; half a skill misleads the model. |
| Fixed platform rules do not fit | Throw (fail closed) | Silently cutting the data-not-instructions rule is worse than failing the run. |
| Budget unit and configuration | Characters (about 4 per token), `maxChars` on the builder with a default | No tokenizer dependency (and no model call). Wiring to an env var is left to AGO-167, which owns worker config for the loop. |
| Run event for a cut | None added. Cuts are logged and returned in `metadata.cuts` | No AGO-164 type fits (`run.limit_reached` only allows steps, tokens or time). Amending the shared event contract is out of scope. |
| Workspace isolation | Workspace from the run row; explicit `workspace_id` on every query; the builder re-checks `workspaceId` and `agentId` of every skill row and drops mismatches (counted in `metadata.skills_rejected`, logged) | The worker connects as `postgres`/service, which bypasses RLS, so the filters are the only guard. Defence in depth covers a faulty query. |
| Independent review | Not spawned | The brief forbids subagents; `/pr-gate` is the independent reviewer. |

## Known limitations
- Assignments follow the latest skill version; there is no pin (needs a schema change; see follow-ups).
- The agent `prompt` is null until the agent wizard stores one; the role is `agents.description`.
- Every stored skill is treated as `owner`. The pack import must record the origin.
- Size is measured in characters, not tokens.
- The vault map is empty until the vault epic provides a provider; the retrieved-content argument is only used once the tool loop passes tool results.
- Escaping is deterministic text neutralisation plus a system rule. The model is the final parser; the real guard against a hijacked agent is the policy engine on every tool call.
- No run event on a cut (see decisions).

## Testing notes
- Vitest `apps/worker/src/context/untrusted.test.ts`: 15 break-out attempts (case, whitespace, zero-width, bidi, fullwidth, hyphen/space variants, fake opening tag), source-label break-out, partial-tag stripping, ordinary text unchanged.
- Vitest `apps/worker/src/context/context-builder.test.ts`: only assigned skills (other agent and other workspace rows from a faulty source are dropped and counted), trusted vs untrusted placement, hostile text in task/pack skill/vault/retrieved cannot close a block, the cap is never exceeded across many caps with every block closed, strict priority order, whole-skill drops, task truncation keeps the title, the log has counts and sources and never the content, fail-closed budget, determinism (including a shuffled source), no-task and unknown-run cases.
- Vitest `packages/shared/src/context/context-schemas.test.ts`: origin is required, strict keys, bounds.
- Live `scripts/ago-145-context-builder.test.mjs` (seed workspace, one transaction that is rolled back, so no runs are left behind for the seed idempotency tests): the seeded agent gets exactly its skill at its current version, other agents' and another workspace's skills never appear, a new skill version is followed, a hostile task cannot close its block, and an over-cap run is cut and logged without content. Run: `node scripts/db-lock.mjs acquire AGO-145`, then `RUN_DB_TESTS=1 pnpm exec vitest run --config vitest.scripts.config.mjs scripts/ago-145-context-builder.test.mjs` (after `pnpm build`), then `node scripts/db-lock.mjs release AGO-145`. Without `RUN_DB_TESTS=1` it skips.
- There is no UI, so no browser walkthrough; the live test's real built output is the equivalent evidence.
