# AGO-115 - Initialize shadcn/ui and design tokens

## Overview
Jira: AGO-115 (US-017), Epic EP-00, Wave 1, blocked by AGO-61 (done). Sets up shadcn/ui in `packages/ui` with Tailwind v4 CSS-variable theme tokens, light/dark themes with no flash, the seven base components (button, card, dialog, sonner, command, table, tabs), and a dev-only gallery route in `apps/web`.

## Implementation details
- **Package shape.** `@ago/ui` now exports TypeScript source (`src/index.ts`); `apps/web` compiles it via `transpilePackages: ["@ago/ui"]`. The old `tsc` build step and `tsconfig.build.json` were removed (an emitted `dist` cannot carry Tailwind classes or `"use client"` cleanly).
- **Tokens, one place to revise.** `packages/ui/src/styles/tokens.css` holds the raw `--ao-*` palette from `docs/art/style-guide.md` section 4 (navy, teal, peach, cream, plus status colours). `theme.css` maps them to shadcn semantic tokens for `:root` and `.dark` and exposes them to Tailwind with `@theme inline`. Changing the art direction means editing `tokens.css` (or the mapping in `theme.css`). Entries marked "derived" in `tokens.css` (navy-900/800, cream-50, teal-300, peach-200, status steps) were made for UI surfaces and are not sampled from the art.
- **Mapping.** Light: background cream-50, foreground navy-700, primary teal-700, accent peach-200, secondary/muted cream-100. Dark: background navy-900, foreground cream-100, primary teal-500, accent orange-500, cards navy-800. Primary is teal-700 in light because cream-on-teal-500 has poor contrast.
- **Dark mode without flash.** `ThemeProvider` wraps `next-themes` (`attribute="class"`, system default). It injects a pre-paint script that sets the class from localStorage or the system preference. The root layout sets `suppressHydrationWarning` on `<html>`. `ThemeToggle` cycles light, dark, system.
- **Components.** Written in the shadcn new-york style on the unified `radix-ui` package, PascalCase file names per CLAUDE.md section 4: `Button`, `Card`, `Dialog`, `Sonner` (Toaster), `Command` (cmdk), `Table`, `Tabs`. All re-exported from `@ago/ui`.
- **Gallery.** `/dev/ui` (`apps/web/src/app/dev/ui/page.tsx`, thin) renders `features/ui-gallery/UiGallery.tsx`. Gated by `isUiGalleryEnabled()`: on in `next dev`, 404 in production unless `ENABLE_UI_GALLERY=1`. Not linked from any navigation. The route is `force-dynamic` so the flag is read at request time.
- `apps/web` imports everything from `@ago/ui` (layout, home page, gallery).

## Decisions taken
Autonomous run (no human at the keyboard); recommended option chosen each time.
| Decision | Chosen | Why |
|---|---|---|
| Package output | Source exports + `transpilePackages` | Simplest for Tailwind class scanning and client components; no dual build. |
| Theme mechanism | `next-themes` | Standard shadcn solution; handles pre-paint class, system preference, persistence. Not a locked-stack swap. |
| `next-themes` version | `1.0.0-beta.0`, pinned exactly | 0.4.6 logs a React 19 console error ("script tag while rendering React component"). The beta does not, and the API we use is unchanged. Revisit when 1.0 is stable. |
| Component creation | Hand-written in shadcn new-york style, no `components.json`/CLI | Deterministic in a monorepo with no interactive prompt; same output as the CLI. |
| Light primary | teal-700 | Contrast against cream text. |
| Gallery route and gating | `/dev/ui`, dev-only plus `ENABLE_UI_GALLERY` opt-in | Matches brief; opt-in lets a preview/test build show it. Env config proper belongs to AGO-70. |
| `@/` import alias | Not added; relative imports | No alias is configured yet; adding one is a repo-wide change. |

## Known limitations
- No lint or test scripts exist yet (AGO-111), so those gates were skipped; no unit or E2E harness yet (AGO-118).
- Dark theme values for border/muted are tuned by eye; the palette itself is v1 and revisable.
- `next-themes` is a pre-release (see decisions).
- Gallery is not covered by automated tests; verified in the browser (see below).

## Testing notes
- `pnpm typecheck` and `pnpm build` pass.
- Manual, Orca embedded browser against `next dev`: system dark gives `html.dark` and body `rgb(27, 35, 48)`; `localStorage.theme=light` plus reload gives `html.light` and body `rgb(247, 242, 232)` (class present on first load, script runs before paint); toggle switches light to dark; dialog, toast, command dialog and tab switch work; table renders 3 rows; all seven gallery sections present; no console errors after the next-themes change.
- Production build: `/dev/ui` returns 404 without the flag and 200 with `ENABLE_UI_GALLERY=1`.
- Run: `PORT=$(node scripts/free-port.mjs) pnpm --filter @ago/web dev`, open `/dev/ui`.
