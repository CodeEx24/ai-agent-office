# AGO-124 - US-056 Publish the event contracts for the office

- Ticket: https://stratyge.atlassian.net/browse/AGO-124
- PRs: https://github.com/CodeEx24/ai-agent-office/pull/76
- Related: AGO-164 (typed run events, done), AGO-126 (realtime + cursor catch-up), AGO-142 (office store), AGO-150 (agent cards, six states), AGO-153 (run view)
- Status: In progress · Type: Feature · Risk: medium · Epic EP-07 · Wave 3

## Overview
Publish, in `packages/shared`, the contract between run events and office state: what every run event type does to the office, as a pure reducer, so the realtime layer (AGO-126), the office store (AGO-142), agent cards (AGO-150) and the run view (AGO-153) all consume one definition. No UI, no schema change, no worker change.

Acceptance criteria (verbatim):
1. Each event type has a defined effect on office state
2. State can be rebuilt from the last N events
3. Tests pass, no regressions, PR reviewed and merged, docs updated (see Definition of Done)

## Design
Code lives in `packages/shared/src/office/` and is exported from the barrel. It reuses `RUN_EVENT_SCHEMAS` / `RunEvent` from `events/` (no parallel enum).

**Input.** `OfficeEventRecord` (Zod): `{ id, workspace_id, run_id, agent_id, seq, type, payload, created_at }`. It is a `run_events` row plus `agent_id` (the loader resolves it from `runs`, workspace-scoped), so every event attributes itself and a window never needs `run.created`. `payload` is the stored `{ version, ...fields }`; it is re-validated with `parseStoredRunEvent`.

**Order.** `seq` is per run (AGO-102), not per workspace. The workspace *feed order* is `(created_at, id)`; `compareFeedOrder` / `sortFeed` define it. Correctness never depends on cross-run order: state is folded per run in `seq` order, and per-agent state is a deterministic function of the agent's runs. **N** = the last N rows of one workspace in feed order. A **cursor** is `{ created_at, id }` of the last applied row (what AGO-126 fetches after); per-run `last_seq` is the exact dedupe/gap marker.

**State.** `OfficeState` (Zod, JSON-serializable, `version: 1`): `workspace_id`, `cursor`, `runs: Record<run_id, RunView>`, `gaps` (runs with missed rows), `anomalies` counters (`unsupported`, `invalid`, `foreign`). Agent state is not stored: `selectAgentStates(state)` derives it from the runs (deviation from the accepted design, recorded here: it removes any chance of agents disagreeing with runs). `RunView` is built from independent **channels**, each last-writer-wins: `phase` (queued, active, paused, stopped, failed, completed), `tool` (in-flight call), `approval` (open request), `handoff`, `step`, plus `last_error` and `last_message`.

**Agent state (six, per AGO-150):** `idle | working | thinking | collaborating | waiting_on_you | error_or_paused`, with a `detail` (the run's reason code, e.g. `user_pause`, `tool_error`). Limit, loop and budget events set the run's `error` channel and do not change its phase (a later `run.stopped` / `run.failed` does). An agent's state is the highest-priority state among its non-terminal runs (waiting_on_you > error_or_paused > collaborating > working > thinking); with none, the latest terminal run decides (completed → idle; failed/stopped → error_or_paused); no runs → idle.

**Effects.** `OFFICE_EVENT_EFFECTS` is a mapped type over every `RunEventType`: adding an event type to `RUN_EVENT_SCHEMAS` fails the typecheck until its effect is defined (AC1), and a test asserts the table is total. Informational events (`budget.usage`, `context.cut`, `policy.decision`, `step.completed`, `tool_call.requested`) are explicitly "no state change" (they still advance `last_seq`).

**Replay rules (pure, deterministic, never throw).**
- foreign `workspace_id` → counted `foreign`, ignored (tenant safety);
- `seq <= last_seq` → duplicate, ignored (idempotent);
- `seq > last_seq + 1` on a known run → not applied, run flagged in `gaps` (caller must catch up from the cursor); never silently skipped;
- unknown run: accepted at any `seq` when rebuilding from a window (`rebuildOfficeState`), only at `seq 1` when applying live (`applyOfficeEvent`);
- unknown event `type` or `version`, or an invalid payload → counted `unsupported` / `invalid`, `last_seq` still advances (the row's `seq` is trusted, its payload is not), state otherwise unchanged;
- agent-supplied text (`message.emitted.summary`, error messages) is stored as bounded data only; the reducer never interprets it.

**Rebuild guarantees (tested, property-style over generated well-formed histories).**
1. **Snapshot + tail = full history**, exactly (the supported path for AGO-126/142: persist `OfficeState`, apply rows after the cursor).
2. **Last-N window**: for every channel whose latest event lies inside the window the value equals the full-history value. A channel whose last event fell outside the window is unknown (empty) and the run is marked `partial: true`. Known consequence: a run silent for more than N events while waiting on an approval needs a snapshot; documented for AGO-126.
3. Full history in any run interleaving (after `sortFeed`) gives the same state; duplicates change nothing.

## Boundaries
- **Always:** workspace scoping on every record; Zod at the boundary; reducer pure and total; append-only assumption (no update/delete events).
- **Ask first:** any change to `RUN_EVENT_SCHEMAS`, migrations, `apps/*`.
- **Never:** interpret agent text; let an event approve anything (the reducer only displays approvals).

## API changes

New exports from `@ago/shared` (`office/`): `OfficeEventRecord`, `OfficeState`, `AgentOfficeState`, `OFFICE_EVENT_EFFECTS`, `applyOfficeEvent`, `applyOfficeEvents`, `rebuildOfficeState`, `selectAgentStates`, `selectTail`, `compareFeedOrder`, `parseOfficeState`, Zod schemas. ## Known limitations
- `created_at` is the transaction start, so feed order can differ from commit order across runs; AGO-126 must dedupe by per-run `seq` and re-query a small overlap before the cursor.
- State keeps every run view; pruning terminal runs is a follow-up for the store.
- Counters (cost, steps) are not part of office state (the run view / budget UI read them elsewhere).

## Testing notes
Vitest only, no database, no model calls: `packages/shared/src/office/*.test.ts` (every type, totality, duplicates, gaps, foreign workspace, unknown version, text-as-data, snapshot + tail, window, order independence).
