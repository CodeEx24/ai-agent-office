# AGO-122 - Add seed data and fixtures

## Overview
Local seed data for development and tests (wave 1). `pnpm db:seed` (and `supabase db reset`) gives a workspace with 3 agents, 5 tasks and starter skills, idempotently, plus typed id constants so later tickets reuse the same data. Jira: AGO-122.

AC: `pnpm db:seed` produces a workspace with 3 agents and 5 tasks (plus starter skills); the seed is idempotent; tests pass and docs are updated.

## Implementation details
- `supabase/seed.sql`: one transaction, fixed UUIDs (`122xxxxx-0000-4000-8000-...`), every insert ends in bare `on conflict do nothing`, so a re-run is a no-op and developer edits are never overwritten. Loaded by `supabase db reset` through `config.toml [db.seed]`.
- `scripts/db-seed.mjs` (`pnpm db:seed`): pipes `seed.sql` into `psql` inside the local Supabase db container via `docker exec` (the container name comes from `project_id` in `config.toml`, or `SUPABASE_DB_CONTAINER`). It never connects by URL, and also refuses to run when `DATABASE_URL`/`*_DB_URL`/`*_SUPABASE_URL` in the environment points anywhere but localhost.
- `packages/shared/src/seed/seed-ids.ts`: typed constants (`SEED_WORKSPACE_ID`, `SEED_AGENTS`, `SEED_SKILLS`, `SEED_TASKS`, `SEED_COUNTS`, owner ids), exported from `@ago/shared`. A Vitest test fails if they drift from `seed.sql`.
- Seeded: 1 workspace, 1 owner member (`seed-owner@agent-office.local`, no password, cannot sign in), agents Scout/Scribe/Reviewer (strict, idle), skills research-summary/note-writing/peer-review (one per agent), tier 0 `vault.read` capabilities granted by the owner, 5 tasks (3 assigned, 2 unassigned, all `todo`).
- Not seeded on purpose: `run_events`, `runs`, `approvals`, `claims`. No fake history or human decisions.

### Decisions taken
| Decision | Choice (recommended) | Reason |
|---|---|---|
| How to make the seed idempotent | Fixed ids + bare `on conflict do nothing` | Also absorbs the `(workspace_id, name)` unique keys; never clobbers local edits |
| How `pnpm db:seed` reaches the DB | `docker exec ... psql` into the local container | Same approach as the repo's other DB scripts; no URL, so a hosted project is unreachable |
| Seed user | `auth.users` row, fake `.local` email, no password | Needed for the owner membership and `granted_by`; no secrets in the repo |
| Fixtures location | `packages/shared/src/seed` | Shared types package, reusable by web, worker and e2e |
| Schema change | None | Existing AGO-74/82/102 tables suffice |

## Known limitations
- The seed owner cannot sign in; sign-in flows keep creating their own users.
- Seeding needs Docker and the local stack (`pnpm db:start`).
- Tier 0 capabilities only; policies and budgets are not seeded (their tables/logic arrive later).

## Testing notes
- `supabase/tests/seed_data.test.sql` (pgTAP, 11 checks): counts, strict/idle agents, tier, no history, no password. Run `pnpm exec supabase test db` inside the db lock after a reset.
- `scripts/db-seed.test.mjs`: local-only guard (always runs) and run-twice idempotency (`RUN_DB_TESTS=1`, inside the db lock).
- `packages/shared/src/seed/seed-ids.test.ts`: fixtures match `seed.sql`; every insert is conflict-guarded; nothing fakes history.
