# AGO-206 - Fix the flaky agent-loop step-limit test

## Overview
**Status: Merged** · Bug, test-only, low risk. Ticket: https://stratyge.atlassian.net/browse/AGO-206. PRs: https://github.com/CodeEx24/ai-agent-office/pull/59

`agent-loop.test.ts` "stops at the step limit" intermittently ended with `loop_detected` instead of
`limit_reached`.

**Root cause:** the test's provider asked for `get_current_time` with the same (empty) input every
step. That tool's output only changes with the clock, so two calls in the same clock tick return
identical output, and loop detection (same call + same output 3 times) fired before step 3.

## Implementation details
The shared `forever()` helper in the "limits" describe now sends a distinct input (`{ n }`) and tool
call id per step, matching the helper already used in the per-agent limits describe. Calls differ
each step, so loop detection can never fire first. No product code and no loop detection change.
