## Overview
`scripts/ago-151-concurrent-start.test.mjs` fails intermittently in the full `pnpm test` gate and passes alone.

## Root cause (reproduced 2 of 2 full runs on main 661b957)
Not a PUBLIC EXECUTE re-grant. The failure is `error: remaining connection slots are reserved for roles with the
SUPERUSER attribute` (Postgres code 53300), thrown by the test's own `grants()` query. The local Postgres has
`max_connections=100` (97 usable). The scripts tests run as parallel files; the concurrent-start file starts 10
workers (each: app pool 4 + pg-boss 4 + more, up to ~12 connections) while `ago-151-acceptance` (6 enqueuer
processes, ~8 connections each) and other DB suites run too, so the slots run out. The same exhaustion also
failed `ago-151-acceptance` AC1 in run 1 ("6 separate processes", an enqueuer got refused). `fileParallelism`
was only off with `RUN_DB_TESTS=1`, which nothing sets.

## Implementation details
1. `vitest.scripts.config.mjs`: `fileParallelism: false` always (files run one at a time).
2. `ago-151-concurrent-start.test.mjs`: the grants check and the PUBLIC re-grant use one dedicated `pg.Client`
   opened before the workers start, not a pool connection. The zero PUBLIC/API-role EXECUTE assertions are unchanged.
3. `ago-201-acceptance.test.mjs` AC4 pins the old "parallel without RUN_DB_TESTS" behaviour; update it to the new rule.
