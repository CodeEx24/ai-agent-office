# AGO-201 - Fix non-blocking review follow-ups from waves 1-2

## Overview
Wave 2 bug, risk tier medium (touches log/telemetry redaction and the rate limiter, no schema). Jira: https://stratyge.atlassian.net/browse/AGO-201. Five small hardening items that the PR gates recorded as non-blocking in AGO-104, AGO-143, AGO-125, AGO-82, AGO-122, AGO-96 and AGO-66. No schema change, so the schema slot (held by AGO-128) was not needed.

Acceptance criteria (verbatim):
- Redaction (packages/shared) also covers sk- keys with dotted tails, bare tokens in URL paths (e.g. /token/<value>), Bearer/apikey values in free-text log messages; tests per shape (AGO-104, AGO-143)
- GET /api/capabilities is rate-limited with the AGO-66 limiter (429 + Retry-After) (AGO-125)
- getActiveWorkspace surfaces query errors instead of swallowing them; onboarding form keeps the user's input after a failed submit (AGO-82)
- db-seed-qa no longer fails after live E2E without a reset and no longer races the run_events suites when run in parallel (AGO-122, AGO-96)
- Rate limiter: trust X-Forwarded-For only behind a configured trusted proxy (env switch, documented) (AGO-66)
- Tests pass, no regressions, PR reviewed and merged, docs updated

## Implementation details
**1. Redaction** (`packages/shared/src/redaction/redact.ts`, used by the worker logger and Sentry scrubbing)
- `sk-`, `sk-ant-` and `sk-proj-` patterns now allow `.` in the tail, so `sk-<part>.<part>` is masked whole. This list is also the source for `scripts/check-client-bundle.mjs`, so the bundle check gets the same coverage.
- `PATH_CREDENTIAL`: the segment after `/token/`, `/tokens/`, `/secret(s)/`, `/password(s)/`, `/credential(s)/`, `/api-key(s)/`, `/access-token/`, `/refresh-token/`, `/bearer/`, `/jwt/`, `/otp/` is masked when it is a value (8+ URL-safe characters). `/tokens/list` and `/api/tokenizer/status` are untouched.
- `BEARER_VALUE` replaces the old Bearer branch: `Bearer x`, `bearer: x`, `Bearer=x`, `"Bearer x"`, and values as short as 4 characters. `Basic` keeps its 8+ rule.
- `API_KEY_PHRASE`: `apikey x`, `api key: x`, `api_key "x"`, `x-api-key: x`, `api key is x`. It deliberately over-redacts the word after "api key".
- Tests build every fake secret at runtime so gitleaks does not flag the source.

**2. Capabilities rate limit** (`apps/web/src/lib/rate-limit/rules.ts`): new rule `apiReadUser` (120 requests per minute, per user; falls back to the IP when signed out) matched for `GET /api/capabilities` in `matchRouteRateLimit`. The existing proxy applies it, so the answer is the standard 429 with `Retry-After` and `RateLimit-*` headers before the route runs. No route code changed.

**3. Workspace lookup and onboarding** (`apps/web/src/features/workspaces`)
- `getActiveWorkspace` throws `WorkspaceLookupError` (generic message, original error on `cause`) for a query error or an unknown stored role. `null` now only means "no membership yet". A new `app/app/error.tsx` boundary shows fixed text and a "Try again" button, so an outage is never shown as the first-run onboarding form.
- `createWorkspaceAction` returns the typed `name` with every error, and `OnboardingForm` uses `defaultValue={state.name ?? defaultName}`. React resets an uncontrolled form after an action, so this is what keeps the input.

**4. db-seed-qa** (`scripts/db-seed-qa.test.mjs`, `supabase/tests/seed_data_qa.test.sql`, `vitest.scripts.config.mjs`)
- The "no run_events, runs or approvals" check counted whole tables, so any E2E or other suite row failed it until a reset. It now counts only rows in the seed's fixed workspace id (as `seed_data.test.sql` already did). The workspace and seed-user lookups use the fixed UUIDs rather than a name or e-mail pattern.
- With `RUN_DB_TESTS=1` the scripts vitest config sets `fileParallelism: false`, so the DB suites run one file at a time inside the db lock. Without it nothing changes.

**5. X-Forwarded-For** (`apps/web/src/lib/rate-limit/client-ip.ts`, `apps/web/src/lib/env.ts`, `packages/shared/src/env/schema.ts`)
- New server variable `TRUST_PROXY_HEADERS` (`true` or `false`, default `false`, declared in the AGO-70 schema, listed as non-secret because the bundle check would otherwise flag the literal `true`). `getClientIp(headers, { trustProxy })` ignores `x-forwarded-for` and `x-real-ip` unless trusted; then it uses the first hop as before. `proxy.ts` passes `shouldTrustProxyHeaders()`.
- Per-user and per-email limits (`limitAction`, the `user:` bucket key) never read these headers and are unchanged.
- Playwright sets `TRUST_PROXY_HEADERS=true` for its web server because the rate-limit specs give each test its own `x-forwarded-for`. `turbo.json` passes it through for `dev`. Documented in `docs/environments.md`.

### Decisions taken (no human at the keyboard; recommended option chosen each time)
| Decision | Chosen | Why |
|---|---|---|
| Capabilities limit: proxy rule vs in-route call | Proxy rule via `matchRouteRateLimit` | One mechanism for every limited route, a real HTTP 429 with the standard headers, and no change to the route or its tests. |
| Capabilities budget | 120 per minute per user | A catalog read by a UI; well above normal use, still bounds scraping. Higher than the 60/min mutation budget because it is read-only. |
| Failed workspace lookup | Throw + error boundary, not an inline message | The caller cannot render a safe page without the answer; the boundary keeps the message fixed and lets Sentry see the cause. |
| Unknown stored role | Also throws | A CHECK constraint makes it impossible; if it ever happens it is corruption and must not look like a new user. |
| Keep onboarding input | Return `name` in the action state | Smallest change that survives React 19's form reset; no client-side state or controlled input. |
| XFF env switch name and shape | `TRUST_PROXY_HEADERS=true`, off by default | A single boolean matches "trust the first hop from a configured proxy"; strict `true`/`false` makes a typo a startup error. |
| Untrusted client address | Shared `unknown` bucket | There is no socket address in the proxy; the existing behaviour for "no header" already failed closed. |
| db-seed-qa isolation | Scope assertions to the seed's UUIDs, serial files under `RUN_DB_TESTS=1` | Removes the dependency on global table state instead of cleaning up after it; serial files cover any remaining overlap. Assertions are not weakened: the seed still must create zero history rows in its workspace. |
| Redaction breadth | Over-redact (prose "api key" word, 4+ char Bearer values, path words) | Brief and CLAUDE.md prefer over-redaction; the path rule still spares `/tokens/list`. |

## API changes
No route added or removed. `GET /api/capabilities` can now answer `429` (`{ error: "rate_limited", message, retryAfterSeconds }` with `Retry-After`, `RateLimit-Limit`, `RateLimit-Remaining`, `RateLimit-Reset`, `RateLimit-Policy`). New optional server env `TRUST_PROXY_HEADERS`.

## Database changes
None. Only a pgTAP assertion (`seed_data_qa.test.sql`) was tightened.

## Known limitations
- With `TRUST_PROXY_HEADERS` off (the default, including plain `next start` and local dev) all callers share one per-IP bucket, so the per-IP sign-in budget (60 per minute) is global. Set the switch on any proxied deployment (Vercel preview and production). `.env.example` is behind a deny rule, so the variable is documented in `docs/environments.md` only.
- "First hop" assumes the trusted proxy overwrites the header. A proxy that appends to a caller-supplied value would still let that caller choose the first entry; that is a proxy configuration issue, not something the app can detect.
- The path rule only masks the segment after a known credential word. A token in an unnamed path position is not caught (the other rules still apply).
