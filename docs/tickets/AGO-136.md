# AGO-136 - US-022 Add the eight role templates

## Overview
Epic EP-03, wave 2 (Agent Runtime + Guardrails), workstream WS-C (Web App and UX), risk tier **medium** (an owner-only authorization surface that creates agents with capability grants, but no schema change). Jira: https://stratyge.atlassian.net/browse/AGO-136. Blocked by AGO-141 (the creation wizard), done.

"As the product owner, I want: add the eight role templates." Manager, Researcher, Analyst, Writer, Reviewer, Developer, Ops assistant and Librarian, with starter prompts, skills and minimal capabilities.

Acceptance criteria (verbatim):
- Each template creates a valid agent in one click
- Researcher has web search and no private notes; Analyst has private notes and no web
- Suggested models are Opus, Sonnet or Fable as in the catalog
- Tests pass, no regressions, PR reviewed and merged, docs updated (see Definition of Done)

A template never grants a permission by itself: it is the owner who clicks, the capabilities are the minimum for the role, a Tier 3 or 4 capability is always "approval", and the agent starts in Strict mode like every agent.

## Implementation details
**Shared** (`packages/shared/src/agents/`):
- `agent-templates.ts` is **zod-free** (like `agent-limits.ts`, AGO-141) so the client can import it from `@ago/shared/agent-templates` without pulling zod into the browser bundle. It holds the eight templates as static typed data (`id, name, summary, role, model, prompt, dailyBudgetCents, capabilities[{key, mode}]`) and `findAgentTemplate`. A template has **no** `mode`, `tier`, `status` or skill-id field, so it cannot ask for anything but Strict mode.
- `agent-template-schemas.ts`: `agentTemplateSchema` (strict zod object; the model must be Opus, Sonnet or Fable, never Haiku) and `agentInputFromTemplate`, which builds the input and validates it with the wizard's own `createAgentSchema`, so a template can never produce an agent the wizard would refuse.

| Template | Model | Budget/day | Capabilities (mode) |
|---|---|---|---|
| Manager | Opus | $5 | vault.read, tasks.manage |
| Researcher | Sonnet | $5 | web.search, vault.read, vault.write_shared (approval) |
| Analyst | Opus | $5 | vault.read, vault.read_private |
| Writer | Sonnet | $5 | vault.read, vault.write_shared (approval) |
| Reviewer | Opus | $5 | vault.read |
| Developer | Sonnet | $10 | vault.read, code.run (approval, Tier 3) |
| Ops assistant | Sonnet | $3 | vault.read, tasks.manage |
| Librarian | Sonnet | $3 | vault.read, vault.write_shared (approval) |

All other keys are automatic only below Tier 3. No template has payments, permanent delete, outbound messages, integration writes or browsing.

**Trifecta (for AGO-138):** no template combines untrusted content (web), private data (own notes) and outbound communication. The Researcher reads the web but has no private notes and no outbound; the Analyst reads private notes but has no web and no outbound. A test asserts it for every template.

**Web** (`apps/web/src/features/agents/`):
- `create-from-template.ts`: `createAgentFromTemplateWith(creator, workspaceId, templateId)` turns the template into the wizard's input and calls the **same** `createAgentWith` and `agentCreator` (so the same `create_agent` RPC): no second code path. Only the name is chosen here; a taken name becomes "Researcher 2", up to 20 tries.
- `actions.ts`: new `createAgentFromTemplateAction`, strict zod input `{workspaceId, templateId}` (template id is an enum), then redirect to `/app/agents`.
- `TemplateGallery.tsx`: eight cards with a "Create <role>" button, shown on `/app/agents` to owners only.
- `AgentWizard.tsx`: a "Start from a template (optional)" picker on the Basics step. It only **pre-fills** the draft (name, role, model, prompt, budget, capabilities); everything stays editable and is reviewed before creating. Capabilities the workspace does not offer are left out; a Tier 3 or 4 one is forced to approval.

### Decisions taken (no human at the keyboard; recommended option chosen each time)
| Decision | Chosen | Why |
|---|---|---|
| Schema slot | None needed; no migration | AGO-148 holds the slot. Templates are static data and creation reuses AGO-141's `create_agent`. |
| Where templates live | Static typed data in `packages/shared`, zod-validated in a test and at use | Brief. No DB table: no RLS surface, no migration, versioned with the code. |
| Zod in the client bundle | Zod-free data file plus a separate zod schema file | Same CSP reason as AGO-128 and AGO-141; `check-client-bundle` still passes. |
| Skills in templates | None; the prompt carries the know-how | Skills are workspace rows with ids (AGO-128), so static data cannot reference them. The ticket says skills are optional. The owner can attach skills in the wizard. |
| One-click path | New server action calling the existing `agentCreator` | One code path: owner-only check, catalog and tier checks, RLS and Strict mode apply unchanged. |
| Unique name | Number the template name ("Writer 2") on a taken name | One click must always work, including the second time. |
| Missing capability in the workspace | One-click fails with a field message; the wizard picker drops it | One click must not silently create a weaker agent; in the wizard the owner reviews the result. |
| Models | Opus for judgement roles (Manager, Analyst, Reviewer), Sonnet for the rest; no Haiku, no Fable | AC3. Fable is the most expensive; a small default budget limits spend. |
| Budgets | $3 to $10 a day, within the $50 platform cap | Small by default (money rule); editable in the wizard. |
| Who can use it | Owners only, checked again on the server | Same as the wizard (AGO-141): members and viewers cannot create agents. |

## API changes
No new HTTP routes. One new server action, `createAgentFromTemplateAction` (session cookie, owner only, strict input `{workspaceId, templateId}`). `/app/agents` shows the template gallery to owners; `/app/agents/new` has a template picker. New export `@ago/shared/agent-templates`.

## Database changes
None. No migration, no new table, no RLS change. Every grant goes through AGO-141's `create_agent`, which already enforces owner-only, the catalog tier and "Tier 3 or 4 is never automatic".

## Dependencies on other tickets
AGO-141 (wizard, `create_agent`, model allowlist), AGO-125 (capability catalog keys), AGO-128 (skill library, zod-free pattern). Unblocks AGO-138 (trifecta lint) and AGO-105 (department starter packs), AGO-117 (Manager splits goals into tasks), AGO-135 (eval set per starter role).

## Known limitations
- No starter skills: a workspace's skills are rows, so a static template cannot attach them (see decisions).
- The one-click path needs every capability of the template to be enabled in the workspace; if an owner disabled one, it says so and the owner uses the wizard picker.
- The model list and templates are code, so changing them is a code change.
- Templates are not editable per workspace and are not staged behind a feature flag (AGO-76 covers rollout).

## Testing notes
- Vitest: `packages/shared/src/agents/agent-templates.test.ts` (for each of the eight: valid, accepted by `createAgentSchema`, catalog accepts every grant, no automatic Tier 3 or 4, model is Opus/Sonnet/Fable, no mode/tier/status field, minimal, no trifecta; plus AC2 for Researcher and Analyst), `apps/web/src/features/agents/create-from-template.test.ts` (one call per template, numbered name, unknown template refused, member/viewer refused, other failures not retried) and new cases in `AgentWizard.test.tsx` (picker pre-fills, stays editable, Tier 3 forced to approval, unavailable capability dropped, no mode sent).
- Live Playwright `apps/web/e2e/agent-templates-live.spec.ts` (`E2E_SUPABASE=1`, 5 tests): each template creates a Strict agent in one click with exactly its grants, Researcher/Analyst AC2 and models AC3 in the database, a second click numbers the name, member and viewer see no templates and cannot open the wizard, wizard picker pre-fills and the owner reviews before creating.
- Run: `node scripts/db-lock.mjs acquire AGO-136`, then `E2E_SUPABASE=1 PORT=<free port> pnpm --filter @ago/web exec playwright test agent-templates-live agent-wizard-live --workers=1`, then `node scripts/db-lock.mjs release AGO-136`. No model API is called.
