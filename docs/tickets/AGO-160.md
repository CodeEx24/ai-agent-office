## Overview
One agent owns a task at a time, and a claim that is not renewed expires so abandoned work frees up.
`public.claims` already exists (AGO-74): one row per claim, a partial unique index `claims_one_active_per_task_idx`
(one row per task with `released_at is null`), `expires_at` nullable, no logic, no fence. This ticket adds the
logic and the missing columns on top of that table.

## Acceptance criteria (verbatim)
- [ ] Given two workers claim the same task, when both try, then exactly one succeeds
- [ ] An expired claim can be taken by another agent
- [ ] Tests pass, no regressions, PR reviewed and merged, docs updated (see Definition of Done)

Derived, testable versions (from the brief's carried-over notes):
- AC1a: a live-DB test fires two claims for one task at the same instant (two connections, barrier) and exactly one wins; no app-level check-then-act.
- AC2a: expiry is judged by the database clock (`now()`), never the worker clock.
- AC2b: after another agent takes an expired claim, the old holder can no longer renew, release or complete (fence token).
- AC2c: a claim by an archived agent is refused (AGO-89 follow-up 2, claim path).
- AC2d: every claim, renew, release, expiry takeover is an append-only event row.

## Design
**Database (one migration `20261114010001_ago_160_task_claims.sql`, rollback + pgTAP).**
- Extend `public.claims`: `claim_token uuid not null default gen_random_uuid()` (the fence; new value on every claim/takeover), `renewed_at`, `release_reason text` (`released`, `completed`, `expired_takeover`, `expired_sweep`), `expires_at` NOT NULL (no seeded rows exist) with a check `expires_at > claimed_at`. Keep the partial unique index as the final backstop.
- Four functions, `SECURITY DEFINER`, `set search_path = ''`, `execute` granted to `service_role` only (revoked from public/anon/authenticated). Humans never call them; agent tokens never reach them because only the worker's service role holds execute.
  - `claim_task(workspace, task, agent, run, ttl_seconds)`: step 1 releases an active claim on the task whose `expires_at <= now()` (logs `claim.expired`); step 2 `insert ... on conflict (task_id) where released_at is null do nothing returning`. Atomic through the unique index, so two concurrent claimers cannot both succeed; the loser gets no row. Refuses an archived or other-workspace agent (55000) and a task from another workspace.
  - `renew_claim(workspace, claim, token, ttl_seconds)`: `update ... where id = $ and claim_token = $ and released_at is null and expires_at > now()`; an expired or fenced claim cannot be renewed.
  - `release_claim(workspace, claim, token, reason)`: same fence; sets `released_at`.
  - `sweep_expired_claims(workspace_id default null)`: releases expired claims in bulk and logs `claim.expired`, so abandoned tasks free up even before anyone takes them.
- TTL: bounded 10..3600 seconds in the function (default 300); a claim with no expiry cannot be created.
- Audit: new append-only `public.claim_events` (workspace_id, task_id, claim_id, agent_id, type, payload jsonb, created_at), same guard as `run_events` (update/delete/truncate revoked and blocked by trigger, tenant-erasure cascade only). Written inside the four functions, same transaction. No secrets in payloads; the token is never logged.
- RLS: members keep read (existing viewer select on claims; same on claim_events); no insert/update/delete for authenticated.

**Worker (`apps/worker/src/claims/`).**
- `ClaimStore` port with a pg implementation that calls the four functions (parameterized, workspace-scoped), a `claimTask` service returning a discriminated result (`claimed {claimId, token, expiresAt}`, `held`, `refused`), and a small `ClaimHeartbeat` helper that renews at TTL/3 and reports loss of the claim to the caller.
- No edit to the agent loop, budget or approvals code. Zod schemas for claim inputs/results go in `packages/shared/src/claims/` (barrel export additive).
- No real model calls.

## Boundaries
- **Always:** scope by workspace_id; database clock for expiry; fence every write with the token; append an event for every state change.
- **Ask first:** touching `tasks.status` semantics, the agent loop, budgets or approvals code.
- **Never:** let an agent claim for another agent; expose the functions to anon/authenticated; log the token; edit or delete claim_events.

## API changes
None over HTTP. Worker-internal `ClaimStore` / `claimTask` / `ClaimHeartbeat` and shared Zod schemas.
