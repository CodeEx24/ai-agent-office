## Overview
Every workspace gets its own git repository holding its Markdown vault, created from `vault-template/`. All reads and writes go through one service (`VaultStore`); nothing else touches the repo. The service confines every path to the workspace's own repo, records who wrote each change (human or agent) as the git author, and refuses agent writes to `_meta/AGENTS.md` and other boot files.

## Implementation notes (built)
- AC 1 (new workspace gets the layout): `git-vault-store.test.ts` "gives a new workspace the starter layout" compares the repo's tracked files to `vault-template/` and checks all seven top folders.
- AC 2 (read and write only through the service): `VaultStore` is the only contract; the path, symlink, isolation, human-only and git-safety tests in `git-vault-store.test.ts` and `vault-schemas.test.ts`.
- AC 3 (AGENTS.md under `_meta`, human-edit only): the "human-only AGENTS.md" tests (agent write and remove refused for case variants, trailing dot or space, nested and boot paths; human write succeeds; file and HEAD unchanged after refusal).
- Concurrency: "survives concurrent first access" runs ensure, write and read from two store instances at once and proves one repo, one initial commit, no temp folders.
- Deviations: (1) Windows aliases (trailing dots and spaces, `~1` short names, device names) are refused in addition to the listed rules. (2) `NUL` (not `os.devNull`) is used as the null device on Windows. (3) `VAULT_ROOT_DIR` is documented in `docs/features/vault.md`, not `.env.example`: the worker session cannot read or edit `.env.example` (permission rule), so that one line is left for the owner.

## Design (proposed)
1. **Interface (`VaultStore`)**, in `apps/worker/src/vault/vault-store.ts`: `ensureVault(workspaceId)`, `read`, `write`, `remove`, `list`, `history`. The git backend (`GitVaultStore`) sits behind it so AGO-144, AGO-165 and AGO-109 build on the interface, not on git.
2. **Location without a migration:** repo path is `<VAULT_ROOT_DIR>/<workspace_id>`, where `workspace_id` must be a UUID (so it can never carry a path). No registry table. `VAULT_ROOT_DIR` is read in the vault module (default `./.vault-data`, added to `.gitignore`).
3. **Provisioning: lazy and idempotent.** `ensureVault` runs at the start of every operation (cheap check for the repo marker). Why not a hook on workspace creation: workspaces are created in the database and web app (other owners' paths, and a DB trigger cannot create files); lazy provisioning also repairs a workspace whose repo was lost and needs no schema. The repo is built in a temp directory (template copy, `git init`, one initial commit) and renamed into place, so two racing callers cannot leave a half repo; the loser discards its copy. `ensureVault` is also exported for the workspace-creation flow to call later.
4. **Starter layout** from `vault-template/`: `_meta/AGENTS.md`, `_meta/README.md`, and `agents/ skills/ projects/ tasks/ inbox/ logs/` (each with `.gitkeep`). A test proves a new workspace's repo equals the template.
5. **Path confinement** (pure lexical check in `packages/shared/src/vault/`, then a filesystem check in the worker). Rejected: empty, NUL, control characters, absolute paths, drive letters (`C:`), UNC / leading slashes or backslashes, any backslash, `..` and `.` segments, empty segments, any `.git` segment (any case), over-long paths. Then each existing component is `lstat`-ed: a symlink anywhere on the path is refused, and the resolved real path must stay under the repo's real path. Case-insensitive matching is used for protected names.
6. **Isolation:** the repo directory is derived only from the validated workspace id; the service never accepts a path to a repo. A test writes in workspace A and proves B cannot read it, including by `../<other-id>/...` and by a symlink planted in A pointing at B.
7. **Human-only `_meta/AGENTS.md`:** the caller supplies a `VaultPrincipal` (`{kind: "human", userId}` or `{kind: "agent", agentId, runId?}`), from trusted code, never from vault or model text. A write or remove by an agent principal on any path classified as a boot path by the existing `classifyBootPath` (AGENTS.md, CLAUDE.md, BOOT.md anywhere, `_boot/`, `.claude/`) is refused with `human_only_path`. Agents may still read it. This keeps one definition shared with AGO-154; AGO-144 will route refused agent attempts to a proposal.
8. **Git safety:** `execFile` with an argument array, never a shell; fixed subcommands; user text only ever goes after `--` as a pathspec (with `GIT_LITERAL_PATHSPECS=1`) or on stdin (`commit -F -`), so it cannot become a flag. Environment is rebuilt from scratch (no user config, no system config, hooks path disabled, no pager, no prompts); `core.autocrlf=false`, `core.symlinks=false`. Vault text is only read and written as bytes/UTF-8; it is never executed or interpolated into a command.
9. **Provenance seam, not provenance:** the git author is `human:<userId>` or `agent:<agentId>` with a fixed `@vault.invalid` address, and an `Agent-Run:` trailer when a run id exists. `history(path)` returns commits with the parsed principal. AGO-165 builds provenance on this.
10. **Limits:** note size max 1 MiB, UTF-8 text only; writes serialized per workspace in-process (git index lock); an unchanged write is a no-op and returns the current commit; a failed commit restores the previous file content.
11. **Shared types:** `packages/shared/src/vault/` holds the path validator, principal schema, layout constants and result types (Zod at the boundary), exported through a one-line barrel addition.

## Boundaries
- **Always:** scope by the validated workspace id; confine every path; record the principal; fail closed.
- **Ask first:** a migration or registry table; a new dependency; changing the root `.gitignore` beyond one line.
- **Never:** let an agent write `_meta/AGENTS.md`; go through a shell; accept a repo path from a caller; build or edit the write tool, provenance or backups.

## API changes
None (no route). The service is a worker module with an interface. A web adapter is not needed by the AC.

## Database changes
None. No registry table; the schema slot is not needed.

## Dependencies on other tickets

## Known limitations
- Needs the `git` CLI on the worker host (already present in dev; the worker container image must include it, noted for the deploy ticket).
- Symlink protection is lstat-based; a hostile process with write access to the repo directory outside the service could race it. The repo directory is service-owned; documented.
- In-process lock only: one worker process per vault root until a later ticket adds a cross-process lock.
- Template is read from `vault-template/` in the repo (`VAULT_TEMPLATE_DIR` overrides).

## Testing notes
Vitest with a temp directory per test, removed afterwards; no database, no network, no model calls. Cases: layout from template, idempotent and racing provisioning, round trip, history principal, path attacks (`..`, absolute, `C:\`, `\\server\share`, NUL, `.git/config`, symlink out, case variants of AGENTS.md), cross-workspace isolation, agent refused on `_meta/AGENTS.md` and boot paths while human succeeds, size limit, no-shell proof (a filename with spaces and `;`, `--flag`-like names stay data).
