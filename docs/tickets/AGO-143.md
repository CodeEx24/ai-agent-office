# AGO-143 - Create the worker service skeleton

## Overview
Wave 2, Jira: https://stratyge.atlassian.net/browse/AGO-143. Builds on AGO-57 (monorepo) and AGO-70 (validated env).
Turn `apps/worker` into a runnable service: validated config at start, a health endpoint, structured JSON logs and a deployable image.

Acceptance criteria (as given in the dispatch brief):
- AC1: the health endpoint returns ok with queue and database status.
- AC2: logs are structured JSON with run and agent IDs.
- AC3: the worker deploys from CI to the target host.
- AC4: Definition of Done (tests pass, no regressions, PR reviewed and merged, docs updated).

Risk tier: medium (a new server-only process and a CI workflow; no auth, data model or agent runtime logic).

## Implementation details
All in `apps/worker/src`:
- `config.ts`: `loadWorkerConfig()` = `loadWorkerEnv()` (AGO-70) plus a Zod schema for `WORKER_PORT`, `WORKER_HOST`, `LOG_LEVEL`, `HEALTH_DB_TIMEOUT_MS`. Errors name variables, never values.
- `logger.ts`: pino JSON logger (`level`, ISO `time`, `service`, `msg`). `withContext(logger, {run_id, agent_id, workspace_id})` returns a child logger binding those ids. A `logMethod` hook scrubs every call: secret-named keys (reusing `isSecretLikeEnvName` from `@ago/shared`, camelCase aware) become `[redacted]`, `scheme://user:pass@host` credentials are stripped from strings and Error messages/stacks.
- `health.ts`: `HealthCheck` interface, `buildHealthReport`, `createPgDatabaseCheck` (`select 1`, one lazy pooled connection, hard timeout) and `queueNotConfigured` (AGO-151 replaces it with a pg-boss check).
- `server.ts`: `node:http` server, `GET /health` and `/healthz` only, everything else 404.
- `main.ts` / `index.ts`: `bootstrapWorker` validates config, starts the server and returns a handle; on failure it writes one fatal JSON line (scrubbed) and `index.ts` exits 1. SIGTERM/SIGINT shut down cleanly. This closes the AGO-70 gap ("call `loadWorkerEnv()` at process start and exit non-zero").
- `apps/worker/Dockerfile` (+ root `.dockerignore`): multi-stage, digest-pinned `node:24-slim`, `pnpm deploy --prod`, non-root user, `HEALTHCHECK` on `/health`.
- `.github/workflows/worker-image.yml`: builds the image on PRs touching the worker (no login, no push), pushes `ghcr.io/<owner>/<repo>/worker:{sha,latest}` on main, plus a manual `deploy` placeholder.
- New dependencies: `pino`, `pg`, `zod` (already used by shared), `@types/pg`. `pg` is also what pg-boss (AGO-151) uses.

## API changes
`GET /health` and `GET /healthz` on `WORKER_PORT`, no auth, no secrets in the body:
`{"status":"ok"|"degraded"|"down","db":{"status":"ok"|"down"},"queue":{"status":"ok"|"down"|"not_configured"},"uptime_s":n}`.
HTTP 200 for ok and degraded, 503 when the database is down. `degraded` means the database is up and the queue is not configured yet.

## Database changes
None. Read-only `select 1`. No migration; the schema slot was not used. The pg-boss schema belongs to AGO-151.

## Dependencies on other tickets
- AGO-70 (done): `loadWorkerEnv()`.
- AGO-151 (later): replaces `queueNotConfigured` with a pg-boss probe behind the same `HealthCheck` interface.
- AGO-107 holds the schema slot and runs in parallel; this ticket does not reset or migrate the stack.

## Decisions taken
| Decision | Chosen (recommended) | Reason |
|---|---|---|
| HTTP layer | `node:http`, two routes | Lightest option; no framework in the locked stack is needed |
| Logger | pino | Usual choice, JSON by default, child loggers for ids; not a stack swap |
| DB probe | `pg` `select 1` with timeout | Cheap, and `pg` is already pg-boss's driver |
| Queue status | `not_configured` behind an interface, overall `degraded` (HTTP 200) | pg-boss arrives in AGO-151; a missing queue must not fail the probe, a down DB must |
| Port variable | `WORKER_PORT` (default 8787), not `PORT` | `pnpm dev` runs web and worker together; both reading `PORT` would collide |
| Bind address | `127.0.0.1` by default, `0.0.0.0` in the image | Health stays local unless the container asks otherwise |
| Config location | worker-local `config.ts`, not `packages/shared` | The variables are worker-only; shared's server env is also parsed by the web app and bundle check |
| AC3 deploy (money rule) | Dockerfile plus CI job that builds, and pushes to GHCR on main; deploy step is a manual, failing placeholder | No host is chosen and none may be bought without the human |
| Workflow shape | Separate `worker-image.yml`, not an edit of `ci.yml` | Keeps the required check names stable; `packages: write` only on that job |
| `.env.example` | Not edited | Protected by a deny rule; new variables are documented in `docs/environments.md` instead |

## Known limitations
- AC3 is only partly met: the image is built in CI and published to GHCR on main, but "deploy to the target host" cannot run until the human picks a host and adds its credentials. The `worker-deploy` job fails on purpose with a clear message.
- `queue` is always `not_configured` until AGO-151.
- The Dockerfile is verified locally, but the GHCR push only runs on main, so it cannot be seen before merge. The PR run exercises the build only.
- The four new variables are missing from `.env.example`.
- `pnpm dev` now also starts the worker.

## Testing notes
- `pnpm --filter @ago/worker test`: 23 Vitest tests across config (defaults, overrides, bad port, shared env failure), logger (JSON shape, ids bound, key redaction, credentialed URLs in messages/values/errors), health (db up/down, queue unknown, throwing probe, HTTP 200/503/404) and bootstrap (exit path, real server start and stop).
- Local smoke run (shared stack, db on 44322): worker returned 200 `{"status":"degraded","db":{"status":"ok"},"queue":{"status":"not_configured"}}`; with `NODE_ENV=production` and no `APP_ENV` it exits 1.
- Container smoke: `docker build -f apps/worker/Dockerfile .`, the container exits 1 without `APP_ENV` and serves `/health` with it.
