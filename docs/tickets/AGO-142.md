# AGO-142 - US-059 Build the office store

- Ticket: https://stratyge.atlassian.net/browse/AGO-142
- PRs: https://github.com/CodeEx24/ai-agent-office/pull/83
- Related: AGO-124 (reducer, state, selectors; reused), AGO-126 (realtime delivery with cursor catch-up; reused), the 3D office scene tickets (read only from this store)
- Status: In progress · Type: Feature · Risk: low · Epic EP-07 · Wave 3

## Overview
A Zustand store that holds the office (per-agent state) for the UI. It is rebuilt from events on load and changes only when events arrive. CLAUDE.md: the 3D scene reads state only from the office store.

Acceptance criteria (verbatim):
1. After reload, the store matches the state before reload
2. Store updates are driven only by events
3. Tests pass, no regressions, PR reviewed and merged, docs updated (see Definition of Done)

## Implementation details
Module `apps/web/src/features/office/store/`:
- `office-store.ts`: `createOfficeStore()` (zustand vanilla). Data: `workspaceId`, `office` (the AGO-124 `OfficeState`), `status` (AGO-126 status). Actions: only `connect({ source, workspaceId })` and `disconnect()`. The state is written only from the AGO-126 controller's `onState` callback, which folds events through the AGO-124 reducer. The returned handle has no `setState`.
- `use-office-store.ts`: the app singleton `officeStore`, `useOfficeStore(selector)`, `useAgentOfficeState(agentId)` and `useOfficeConnection(workspaceId, source)`.
- Selectors `selectOfficeAgentStates` / `selectOfficeAgentState` wrap the shared `selectAgentStates`, memoized on the office object (stable references, no re-render without a change).
- `zustand` 5.0.16 added to `apps/web/package.json` (already in the lockfile through drei).

Reuse: AGO-124 and AGO-126 are consumed unchanged.

## Decisions
| Decision | Who / when |
|---|---|
| No design forks and no owner question (low risk; the brief fixes the approach). | worker, 2026-11-18 |
| Reload rebuilds from the stored events (cursor catch-up from an empty office), never from a persisted snapshot of derived state. | brief, 2026-11-18 |
| Workspace switch resets the store and closes the old stream. | brief, 2026-11-18 |

## Boundaries
- **Always:** one workspace's events only; the state changes only through the shared reducer.
- **Ask first:** persisting any derived state; a second writer of the office state.
- **Never:** a setter or UI action that writes derived state directly.

## Known limitations
- A reload re-reads the whole feed (bounded by the AGO-126 paging caps) before the office is complete; `status` is `catching_up` meanwhile. A server-side snapshot or window is a follow-up if feeds grow large.
- No UI is added; consumers wire `useOfficeConnection` with a Supabase source (AGO-126 `createSupabaseOfficeSource`).

## Testing notes

Covers: no write API besides connect/disconnect; state equals the shared reducer's fold; reload from the log (plus events missed while gone) deep-equals the pre-reload state; duplicates, out-of-order delivery and overlap; workspace switch and foreign rows; memoized selectors.
