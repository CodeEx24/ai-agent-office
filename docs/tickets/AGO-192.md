## Overview
A human exports one, several or all agents, with only the skills those agents use, to a single deterministic JSON pack (format v1, `packages/shared/src/packs`). One code path serves the API route and `pnpm pack:export`.

## Acceptance criteria (verbatim from Jira)
- [x] AC1: Given selected agents, when exported, then the pack includes those agents and only the skills they use
- [x] AC2: Output is deterministic (sorted keys and arrays) and includes a SHA-256 checksum of the content
- [x] AC3: Capabilities are exported as names and scopes only; no credentials or tokens appear anywhere in the file
- [x] AC4: Export is available through the API and logged as an event with the exporter and agent list
- [ ] AC5: Tests pass, no regressions, PR reviewed and merged, docs updated (see Definition of Done)

## Design
**Pure core in `packages/shared/src/packs/` (additive, new files):**
- `canonical-json.ts`: `canonicalJson(value)` writes sorted object keys and no whitespace. Arrays keep the order the builder gave them. (Browser-safe, exported from the `@ago/shared` barrel.)
- `agent-pack-export.ts` (node only, imports `node:crypto`, exported as `@ago/shared/pack-export` so the browser bundle never pulls it in): `buildAgentPack(source, { now, appVersion, name })` takes plain rows, maps them to the v1 shape, sorts agents by name, skills by name, capabilities by name, then validates with `agentPackSchema` (which also rejects secret-shaped text, so a planted token fails the export instead of leaking). Returns `{ pack, json, checksum }`; `json` is `canonicalJson(pack)` plus one `\n`. Also `computePackChecksum`, `withoutChecksum`, `verifyPackChecksum`.
- Checksum: SHA-256 (lowercase hex) of the UTF-8 bytes of `canonicalJson(pack without the checksum field)`, exportedAt included, no trailing newline in the hashed bytes.

**Data loading (server only, client passed in):** `apps/web/src/features/packs/export-agent-pack.ts` reads agents, `agent_skills` + `skills`, `agent_capabilities` + `capabilities` (scope) through the caller's RLS-bound client, scoped by `workspace_id`, then calls the pure core. It selects named columns only (never `select *`; never credentials, identities, run_limits, runs, budgets usage).

**Field mapping:** name, role, model, prompt from `agents`; `thinkingEffort` from `thinking_effort`; `autonomyMode` from `mode`; `dailyBudgetCents` from `daily_budget_cents` (null becomes `AGENT_DAILY_BUDGET_DEFAULT_CENTS`, because v1 requires a number); capabilities = catalog `key` + `scope` for each granted capability (tier, mode, granted_by dropped); skills = name, version, body of the skills the selected agents use. Not exported: department (no departments table yet, AGO-108), secretRefs (no agent stores refs yet), notes (vault is out of scope).

**Selection:** one, several or all agents. "All" means active (non-archived) agents; an archived agent is exported only when named. An unknown or foreign id gives a not-found error and no partial pack.

**API:** `POST /api/agent-packs/export` (thin route). Body `{ workspace_id, agent_ids?: uuid[] (omit = all active), name? }`, Zod at the boundary. `rejectAgentCredential` first (human-only), then `requireWorkspaceRole(workspaceId, "member")`. Response: the pack JSON with `Content-Disposition: attachment` and `Cache-Control: private, no-store`. 401 signed out, 403 not allowed or agent token, 404 agent not found, 400 bad input.

**Event (AC4):** append-only table `pack_events` (workspace_id, kind 'export', exported_by member id, agent ids and names, skill count, checksum, created_at), written in the same request before the file is returned; if the write fails the export fails (no unlogged export). No pack content or secrets in the row. Needs a migration: see Decisions (AGO-192-q2).

**CLI:** `pnpm pack:export --workspace <uuid> [--agent <id> ...] [--name text] [--out file]` runs the same function. Script lines in the root and `apps/web` `package.json` (the root one builds `@ago/shared` first); the entry is `apps/web/src/features/packs/cli/pack-export.ts`, which runs under Node 24 native type stripping (no new runtime dependency), with behaviour in `run-pack-export.ts` so it is testable with injected dependencies. Auth: AGO-192-q4.

**Secret safety (AC3):** capability objects are rebuilt from two strings; the schema is strict; `findSecretShape` runs over every string; a test plants credential-looking values (built at runtime) in prompts, skill bodies, capability rows and in columns the exporter must not read, and scans the whole serialized file.

## Boundaries
- Always: workspace_id scoping with RLS, human-only route, Zod at the boundary, named columns only, one shared code path.
- Ask first: the v1 schema shape (AGO-192-q3), a migration (AGO-192-q2).
- Never: write ids, credentials, run history, budgets usage or policies into a pack; touch budget, approvals or agent-loop code (AGO-40, AGO-51).

## API changes
New `POST /api/agent-packs/export`. No change to existing routes.

## Database changes
Migration `supabase/migrations/20261114020001_ago_192_pack_events.sql` (rollback `supabase/rollbacks/20261114020001_ago_192_pack_events.down.sql`): new `public.pack_events` (RLS on; members read; append-only trigger blocks UPDATE, DELETE and TRUNCATE for every role, including the table owner) and `public.record_pack_export(workspace, agent_ids, skill_count, checksum)`, the only writer: security definer, `search_path = ''`, executable by `authenticated` only, requires `private.is_member(ws, 'member')`, pins the exporter to the caller's member id, takes agent names from its own `agents` table, and raises P0002 for an unknown or foreign agent id. Five existing pgTAP inventory tests were updated for the new table and function (counts only), as AGO-160 did for `claim_events`.

## Dependencies on other tickets
AGO-191 (schema). No overlap with AGO-40 or AGO-51.

## Known limitations
No departments, secretRefs or notes in the pack yet; a null budget exports as the default; exportedAt makes two real-time exports differ (a test uses a fixed clock).

## Deviations
- `.env.example` was not edited: the tool is denied by permission settings in this session. The four variable names are documented in `docs/features/agent-packs.md` and `docs/actions/set-pack-cli-password.md`; adding the names (no values) to `.env.example` is left to the owner.
- `docs/actions/README.md` (the generated to-do list) was not created: the repo has no `docs/actions/` folder and no generator script yet. The new guide carries the required front matter.
- The CLI entry sets `allowImportingTsExtensions` in `apps/web/tsconfig.json` (the CLI files import siblings with a `.ts` extension for Node type stripping; `noEmit` is already on, so there is no build effect).
- `@types/node` was added to `packages/shared` devDependencies (the node-only builder imports `node:crypto`).
