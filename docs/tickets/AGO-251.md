# AGO-251 - Stabilize the egress docker tests so the worker gate passes on main

## Overview
`egress.docker.test.ts` (1 test) and `egress-acceptance.docker.test.ts` (4 tests) failed on branches that do not touch egress code with `expected '<container id>' to be ''` in the "leaves nothing behind" assertions. Both asserted that NO container or network in the whole docker daemon carried the global `ago.egress` label, so any proxy left by an earlier, crashed or concurrent run (another worktree's gate shares the daemon) failed the next run.

## Implementation details
- New `apps/worker/src/egress/docker-test-support.ts`: the shared `docker()` and `dockerReady()` helpers (previously duplicated in both tests) and `createRunScope()`.
- A run scope hands out run ids unique to the test process (`<name>-<pid>-<nonce>`). Its `leftovers()` checks the egress-run and sandbox-run labels, and egress networks by run label, for exactly those ids. Its `cleanup()` (called from `afterAll`) force-removes only what those ids created.
- Both tests use scoped run ids for every run and check leftovers through the scope. No assertion was weakened: each still asserts that nothing the test created is left behind, and the checks in the acceptance file still assert the same absence (now for the run's own proxy, sandbox and network).

## Boundaries
- **Always:** remove only resources labelled with this process's own run ids.
- **Ask first:** any global `docker rm` / prune in tests.
- **Never:** delete a container the test did not create.
