# AGO-138 - US-023 Add the trifecta lint to the agent wizard

- PRs: (pending)
- Related: AGO-141 (wizard, done), AGO-125 (capability catalog, done), AGO-136 (role templates, done), AGO-89 (edit/duplicate/archive, parked; will reuse the lint)

## Overview
Epic EP-17, wave 2, workstream WS-E (Security and Governance). Risk **medium** (security surface: it adds a guard on agent creation, no schema, no auth change). "Block an agent from combining untrusted content, private data and outbound communication without a security admin approval."

Acceptance criteria (verbatim):
- Given a capability set containing all three, when saved, then it is blocked with an explanation
- Researcher and Analyst templates pass the lint
- Tests pass, no regressions, PR reviewed and merged, docs updated (see Definition of Done)

## Implementation details (proposed)
- `packages/shared/src/agents/trifecta-lint.ts`, zod-free (same reason as `agent-limits.ts`), exported as `@ago/shared/trifecta-lint`: a static map from capability key to leg (`untrusted`, `private`, `outbound`) and `lintTrifecta(keys)` returning `{ ok: true }` or `{ ok: false, legs, message }`. The message names the three legs and the capabilities that cause each, and says what to remove.
- Server enforcement at the one choke point: `agentCreator.createAgent` (covers the wizard and create-from-template), after `resolveCapabilityGrants`. Failure is a field error on `capabilities` (`AgentLibraryError("invalid", "capabilities", message)`), mapped in `create-agent.ts`.
- Wizard (additive): the Capabilities step and Review step show the explanation live as soon as the ticked set holds all three, using the same pure function; Next/Create stay blocked with the message in `role="alert"` on the capabilities field.
- Tests: lint unit tests (all 8 legs combinations, mode ignored, unknown keys ignored), every template passes (replaces the inline check in `agent-templates.test.ts` with the shared lint, additive), `agentCreator` refuses the trifecta before any RPC, wizard shows the explanation and blocks.
- Docs: section in `docs/features/agents.md`.

## Boundaries
- **Always:** lint on the server as well as in the UI; the request never carries a leg or an override.
- **Ask first:** a migration or DB check (the schema slot is held by AGO-30); a new role.
- **Never:** let an agent or the creating owner bypass the block in this ticket; edit AGO-89's files.

## API changes
None (a new refusal message on the existing create actions).

## Known limitations
- The map covers the 12 starter capabilities; a key not in the map has no legs (fail-open for future catalog entries, flagged in tests so a new capability forces a decision).
- No approval path exists: the "without a security admin approval" part of the ticket is deferred by the owner (Decisions q2). Until then the combination is always blocked.
