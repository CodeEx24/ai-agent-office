## Overview
Show the live log, steps, tool calls, tokens, cost and duration for one run, on `/app/runs/[runId]`.

## Acceptance criteria (verbatim)
- [ ] Log updates live
- [ ] Cost and tokens match stored usage
- [ ] Tests pass, no regressions, PR reviewed and merged, docs updated (see Definition of Done)

## What the repo already stores (findings)
| Need | Stored source | Readable by the web app? |

## Design
- **Truth for cost and tokens:** the sum of the run's `budget.usage` events (the stored usage recorded on the run events). The client never estimates and never reads a price table. A run stopped by `budget.exceeded` shows the same sum plus a stop banner built from that event (scope, reason, used, limit). Cents are summed as written (`cost_cents`); when only `cost_micros` exists it is shown from micros. A call with no recorded cost shows "n/a", not 0.
- **Route:** `apps/web/src/app/app/runs/[runId]/page.tsx`, thin. It checks the session, picks the active workspace, validates `runId` as a uuid, loads the run (`workspace_id` + `id`, user client, RLS) and its events in `seq` order, and renders `RunView`. A missing run, a run of another workspace or a malformed id all give the same not-found state, with no data.
- **Module:** `apps/web/src/features/runs/run-view/`.
  - `run-log.ts`: pure fold of event rows into `RunLog` (header facts, steps, tool calls joined by `call_id`, usage totals, timeline entries). Deduplicates by `seq`, orders by `seq`, reports gaps. Validates each row with the AGO-164 schemas; unknown or invalid rows become a visible "unrecognised event" line, never a crash.
  - `run-log-feed.ts`: live feed over the AGO-126 `OfficeEventSource` port. Initial rows come from the server, then `subscribe` (filtered to this `run_id`), `fetchRunEvents(afterSeq)` closes gaps and catches up after a reconnect. Applying the same row twice changes nothing.
  - `RunView.tsx` (client) and small presentational parts: header (status, agent, started, duration), totals (tokens in/out, cost), timeline, tool-call rows with an expand control, stop/failure banner, states (loading, empty, queued, running, paused, stopped, failed, completed).
- **Duration:** `started_at` to `finished_at`, or to "now" while the run is active, ticking once a second; paused time is shown as paused, not hidden.
- **Untrusted text:** all agent and tool text (message summaries, error messages, tool names) is rendered as React text nodes only. No `dangerouslySetInnerHTML`, no Markdown. Long text is cut at a limit with an expand control.
- **Data access:** one read-only function `loadRunView(workspaceId, runId)` in the workspace-scoped data layer, user session only. No service role, no writes, no migration.
- **Client bundle:** client components import `@ago/shared/...` sub-paths only (events, office), never the root barrel.

## Open questions and my recommendations
1. **Tool inputs and results.** The ticket says to show the stored scrubbed inputs and results, but the web app cannot read them: events hold hashes, and the scrubbed text sits in a table with no API grant. Showing it needs a migration or RPC, which this ticket does not own (schema slot is AGO-113's).
   **Recommended:** ship now with what is stored and readable: tool name, tier, policy decision, status, duration, `input_hash` / `output_hash` (shortened), error code and message. Raise a follow-up ticket "store scrubbed tool I/O for the run view" (it needs the schema slot). The render and expand-control code is built and tested with fixture data so the follow-up only adds the source.
   Alternative: wait for the schema slot and add the RPC here.
2. **Browser Supabase client.** The live feed needs a user-scoped browser client. `apps/web/src/lib/supabase/browser.ts` arrives with AGO-150 (PR 87, open).
   **Recommended:** build against the `OfficeEventSource` port with a fake in tests, and wire the real client after PR 87 merges (merge `origin/main`, no duplicate). Until then the page renders the server-loaded log without the live part.

**Stored source of truth for cost and tokens:** the run's `budget.usage` events on `run_events`. The worker emits one right after each settlement against the AGO-40 ledger, with the settled `cost_cents`, so the sum equals what the ledger recorded for that run.

## Boundaries
- **Always:** scope every query by `workspace_id` as the signed-in user; render agent text as plain text; read only.
- **Ask first:** any migration or RPC; changes to the office contract.
- **Never:** write `run_events`; use a service role in the web app; call a real model; render agent text as HTML.

## Testing notes
Unit: `run-log` fold (steps, tool call join, usage totals equal the sum of stored `budget.usage` events, including a run ended by `budget.exceeded`; duplicates; gaps; unknown events). Feed with a fake source: a new row appears without reload; a reconnect catches up with no duplicates and no gaps. Component tests: every state, plain-text rendering of a hostile string, expand control, ticking duration (fake timers). Data function: not-found for a missing or foreign run. Device test with seeded data under the db lock.
