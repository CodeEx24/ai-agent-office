# AGO-126 - US-057 Add realtime delivery with cursor catch-up

- Ticket: https://stratyge.atlassian.net/browse/AGO-126
- PRs: https://github.com/CodeEx24/ai-agent-office/pull/77
- Related: AGO-124 (office event contract, merged), AGO-107 (RLS), AGO-102 (run_events append-only), AGO-142 (office store, consumes this), AGO-84 (holds the schema slot)
- Status: In progress · Type: Feature · Risk: high · Epic EP-07 · Wave 3

## Overview
Stream `run_events` to the browser with Supabase Realtime and catch up from a cursor after a reconnect, so the office never misses an event and never sees another workspace's events. No UI. The office store (AGO-142) will call a small typed API from this module; the store itself is not built here.

Acceptance criteria (verbatim):
1. Given a dropped connection, when it returns, then missed events are fetched and applied in order
2. Events from other workspaces never arrive
3. Tests pass, no regressions, PR reviewed and merged, docs updated (see Definition of Done)

## Design
Module: `apps/web/src/features/office/realtime/`. It consumes the AGO-124 contract from `@ago/shared` (`OfficeEventRecord`, `applyOfficeEvent(s)`, `OfficeState`, `compareFeedOrder`) and does not change it.

- **Pieces** (all framework-free, injected dependencies, so they are testable with fakes):
  - `loadOfficeEvents` (catch-up): a workspace-scoped query on `run_events` (RLS as the guard, explicit `workspace_id` filter as defence in depth) from the cursor minus a small overlap (`created_at >= cursor.created_at - OVERLAP`), ordered `(created_at, id)`, paged. Each row is joined to its run's `agent_id` through a workspace-scoped read of `runs`, validated with the office event record schema, and rows of another workspace are dropped and counted.
  - `subscribeOfficeEvents`: Realtime Postgres Changes on `public.run_events`, `INSERT`, filter `workspace_id=eq.<id>`. Every payload is re-validated and its `workspace_id` re-checked before it is applied.
  - `createOfficeRealtime` (controller): owns the lifecycle. On start it catches up first, then streams. Live rows go through `applyOfficeEvent`; a row ahead of its run (`state.gaps`) triggers catch-up. On channel close, error, timeout or the browser coming back online it reconnects with backoff and catches up from `state.cursor` with the overlap. Events are applied once each, by per-run `seq`, so overlap and duplicates are free (AGO-124 guarantee).
  - Ordering: events that arrive during a catch-up are buffered and applied after it, sorted by `(created_at, id)`; correctness comes from per-run `seq`, and a hole is held until the gap is filled.
- **Typed API for AGO-142:** `createOfficeRealtime({ client, workspaceId, initialState, onState, onStatus })` returns `{ start, stop }`; status is `connecting | live | catching_up | reconnecting | stopped`.
- **Security:** RLS `run_events_select_viewer` (AGO-107) is the real guard for both the query and Realtime (Postgres Changes evaluates RLS per subscriber). The client is the user-scoped Supabase client (anon key + user session); no service role in the browser. Agent tokens are not used on this path. Agent text in payloads stays untrusted data (the reducer never interprets it).
- **Deviation (2026-11-17):** a gap is filled by a per-run fetch (`seq > after_seq`) in addition to the cursor catch-up, because a row lost while connected can be older than the overlap.
- **Live integration tests (under the db lock):** two workspaces, a subscriber in A never receives B's inserts, catch-up never returns B's rows; a reconnect test drops the channel, inserts while down, reconnects and asserts each missed event applied once, in order, with duplicates and overlap handled.

## Boundaries
- **Always:** scope every query by workspace; RLS as the guard; validate each row with Zod; apply by per-run `seq`; run_events read only.
- **Ask first:** any migration (the schema slot is AGO-84's); changes to `packages/shared/src/office/**`.
- **Never:** update or delete `run_events`; use a service role client in the browser; interpret agent text.

## API changes
None over HTTP. The browser reads through RLS directly, so no catch-up route is planned.

## Database changes
`supabase/migrations/20261117020001_ago_126_realtime_run_events.sql` adds `public.run_events` to the `supabase_realtime` publication (guarded, so re-applying is harmless). Rollback: `supabase/rollbacks/20261117020001_ago_126_realtime_run_events.down.sql` (drops it from the publication; rows and RLS untouched). No new table, column or policy: the existing `run_events_select_viewer` policy is what Realtime evaluates per subscriber. Checks: `supabase/tests/realtime_run_events.test.sql` (pgTAP) and `scripts/ago-126-rollback.test.mjs` (round trip). Schema slot granted by the orchestrator after AGO-84 merged (b1ef897), 2026-11-17.

## Known limitations
- No UI and no store; the store wires `createOfficeRealtime` (AGO-142).
- Catch-up loads are bounded (40 pages per load, 20 loads per catch-up); a truncated load continues from its last keyset position, and the controller never goes live with a backlog left (it errors and reconnects). A very long outage is still best served by the AGO-124 snapshot path.
- Realtime does not apply RLS to `DELETE` events (security review nit, round 1). `run_events` DELETE is RESTRICTed (migration `20261105100001_ago_102`), so no DELETE events occur today; AGO-147 must revisit DELETE events if retention ever deletes rows. Documented in `docs/features/office-events.md`. No schema change.
