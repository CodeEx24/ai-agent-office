## Overview
Cards for each agent showing one of six states (Idle, Working, Thinking, Collaborating, Waiting on you, Error or Paused) "so that I can see everything at a glance". State comes only from the office store (AGO-142). The "Waiting on you" badge is the human-in-the-loop entry point: it opens the approval, and never decides it.

Acceptance criteria (verbatim):
1. Each state has a distinct badge and color-independent label
2. Waiting on you shows a red badge and opens the approval card
3. Tests pass, no regressions, PR reviewed and merged, docs updated (see Definition of Done)

## Implementation details (proposed)
Module `apps/web/src/features/office/cards/` (next to the store it consumes; the 3D scene tickets share `features/office`).
- `agent-state-view.ts`: a table from each `AgentOfficeStateName` to label, icon, short description and badge tone. Exhaustive (`satisfies Record<...>`), so a seventh state fails to compile.
- `AgentStateBadge.tsx`: text label + distinct inline icon/shape + tone class; accessible name "Agent state: <label>". Color is never the only signal (WCAG 1.4.1).
- `AgentCard.tsx`: agent name/role, badge, detail (reason code as plain text), error/message text as plain text only. For `waiting_on_you` the badge is a link to the approval in the inbox; it only navigates.
- `AgentCardGrid.tsx` (client): `useOfficeConnection`, `useOfficeStore(selectOfficeAgentStates)`, a stream-status banner (connecting, catching up, reconnecting, stopped), empty and loading states. Agents with no run show Idle.
- Route: new thin page `apps/web/src/app/app/office/page.tsx` loads the agent list server-side (`listAgents`) and renders the grid.
- Docs: `docs/features/flat-view.md`.

Tokens: shadcn `Card` from `@ago/ui` plus existing semantic tokens (`destructive` for red, `muted`, `primary`); contrast checked in light and dark.

## Boundaries
- **Always:** read office state only through the store hooks; render agent text as plain text; workspace comes from the user's membership.
- **Ask first:** changes to the store, shared contract, approvals decision logic, schema.
- **Never:** approve or deny from a card; fetch run_events directly in a component; edit run_events.

## Open points (need the owner)
1. **Browser Supabase client.** The store needs an `OfficeEventSource`; `createSupabaseOfficeSource` needs a user-scoped browser client, and the repo has only `lib/supabase/server.ts`. Recommended: add `apps/web/src/lib/supabase/browser.ts` (`createBrowserClient` from the already-installed `@supabase/ssr`, additive). It is outside the brief's owned list, so this is a SCOPE ask.
2. **Where "opens the approval card" goes.** Recommended: link to `/app/approvals#approval-<approval_id>-title` (the inbox titles already carry that id; no change to the approvals feature). A decided or missing approval has no card in the inbox, so the badge also shows a short note that it may already be decided. Alternative: a new `/app/approvals/[id]` page (more code, touches the approvals feature).
3. **Route.** Recommended: new `/app/office` page for the card grid, plus a link from `/app`. Alternative: replace the `/app/agents` list.
