# AGO-104 - Add error tracking and structured log shipping

## Overview
Wave 2, Jira: https://stratyge.atlassian.net/browse/AGO-104 (US-051, epic EP-12 Observability and cost).
Blocked by AGO-143 (worker skeleton) and AGO-61 (Next.js 16), both done.
Adds Sentry error tracking to the web app and the worker, and documents how structured logs are shipped.

Acceptance criteria (verbatim from the ticket):
- AC1: An injected error appears in Sentry with run ID.
- AC2: Secrets are scrubbed from error payloads.
- AC3: Tests pass, no regressions, PR reviewed and merged, docs updated (see Definition of Done).

Risk tier: medium (new third-party SDKs in both processes, a CSP change, a redaction rule set; no auth, data model or agent runtime logic).

## Implementation details
- `packages/shared/src/redaction/` (new, client-safe, exported from the barrel and as `@ago/shared/redaction`):
  - `redact.ts`: `scrubString` (credentialed URLs, JWTs, `sk-`/`sb_secret_`/`ghp_`/... shapes, `Bearer`/`Basic` values, `apikey=`/`token=`/`password:` pairs, PEM blocks), `isSecretKey` (the same deny-by-default rule as `isSecretLikeEnvName`, written out locally with no imports so the browser bundle does not ship the env schema; `redact.test.ts` pins the two together. Adds `cookie`/session keys, kebab- and camelCase aware), `scrubValue` (log payloads, depth 6), `scrubTelemetryEvent` (whole Sentry events and breadcrumbs, depth 24 so stack frames survive; keeps only `user.id`). Cycle safe.
  - `SECRET_VALUE_PATTERNS` moved here from `scripts/check-client-bundle.mjs`, which now imports it (one list, two users).
  - `telemetry-policy.ts`: `TELEMETRY_DATA_COLLECTION`, every Sentry v11 `dataCollection` category off.
- Worker (`apps/worker/src`):
  - `logger.ts` now uses the shared redactor (closes the AGO-143 follow-up: bearer/apikey values inside log message strings). New optional `onLog` sink, called with each scrubbed entry plus the bound run/agent/workspace ids.
  - `sentry.ts`: `createErrorTracker({dsn, environment, transport?})` returns a no-op tracker when there is no DSN (the SDK is never touched). With a DSN: `dataCollection` off, `tracesSampleRate: 0`, no local variables, `beforeSend`/`beforeBreadcrumb` scrub. `captureException(error, {run_id, agent_id, workspace_id})` sets those as tags inside `withScope` so they cannot leak to the next error. `registerFatalErrorHandlers` logs, reports, flushes (2 s) and exits 1 on uncaught exceptions / unhandled rejections; Sentry's own handlers for those are removed so the exit path is ours.
  - `config.ts` exposes `sentryDsn`; `main.ts` builds the tracker, feeds log lines to it as breadcrumbs and closes it in `stop()`; `index.ts` registers the fatal handlers.
- Web (`apps/web/src`):
  - `instrumentation.ts`: `register()` initialises `@sentry/nextjs` only when `SENTRY_DSN` is set; exports `onRequestError`.
  - `instrumentation-client.ts`: browser init only when `NEXT_PUBLIC_SENTRY_DSN` is set; Replay and browser tracing integrations filtered out.
  - `lib/sentry/options.ts`: shared option builder (scrubbing + `dataCollection` off + no tracing).
  - `lib/security/csp.ts` / `proxy.ts`: optional `sentryDsn`; its origin (never the key) joins `connect-src` only when a DSN exists.
  - `lib/env.ts` (`getSentryDsn`) and `lib/env/client.ts` read the new public variable.
- `packages/shared/src/env/client-schema.ts`: `NEXT_PUBLIC_SENTRY_DSN` added to `clientEnvSchema` (it was explicitly forbidden before; the AGO-70 tests that listed it as forbidden / not in the documented set were updated).
- Dependencies: `@sentry/node@11.11.0` (worker `dependencies`, so `pnpm deploy --prod` ships it) and `@sentry/nextjs@11.11.0` (web), pinned to the same exact version so there is one `@sentry/core`.

## Decisions taken
Taken by the agent (no human at the keyboard), recommended option each time.
| Decision | Chosen (recommended) | Reason |
|---|---|---|
| Sentry plan / cost | Free Developer plan only; no Replay, Profiling, tracing, Seer; no `SENTRY_AUTH_TOKEN` | Money rule; the human creates the account and DSN |
| Optionality | No DSN means no `init`, nothing buffered or sent | Brief: app and worker must run normally without Sentry |
| Web wiring | `instrumentation.ts` + `instrumentation-client.ts`, no `withSentryConfig` | Source maps and tunnelling are out of scope; avoids rewriting the Turbopack config |
| PII switch | `dataCollection` all off (`TELEMETRY_DATA_COLLECTION`) | Sentry v11 removed `sendDefaultPii`; its `dataCollection` defaults collect cookies, headers and bodies |
| Redactor home | `packages/shared`, subpath `@ago/shared/redaction` for the browser | One rule set for logs and Sentry; barrel carries server schema so the client needs a subpath (same as `client-env`) |
| Secret-shape list | Moved into shared; `check-client-bundle.mjs` imports it | Reuse-first, avoids a drifting duplicate |
| Event scrubbing | Deep, depth 24, whole event | Targeted-field scrubbing would miss new fields; depth 6 would erase stack frames |
| Process fatal errors | Our own handlers (log, report, flush, exit 1); Sentry's removed | Deterministic flush and exit, testable with a fake `process` |
| Log shipping | Document that the host collects stdout; log lines also become breadcrumbs | No paid log service; stdout JSON is already structured and scrubbed |
| Browser DSN | `NEXT_PUBLIC_SENTRY_DSN` declared in `clientEnvSchema`; `next.config.ts` `env` always inlines it (`""` when unset); `instrumentation-client.ts` reads the literal and checks `URL.canParse` instead of `getClientEnv()` | Deny-by-default public variables; a DSN is public by design. Importing the env schema into the browser, or leaving a live `process.env.NEXT_PUBLIC_SENTRY_DSN` reference, put `SENTRY_DSN` / `SERVICE_ROLE` strings in the client bundle and tripped the AGO-67/70 bundle guards |
| Redactor imports | `redact.ts` has no imports (own key matcher) instead of reusing `isSecretLikeEnvName` | Importing `client-schema` shipped its `SERVICE_ROLE` denylist to the browser (AGO-67 guard). A drift test compares both matchers on 20 names |
| `.env.example` | Not edited (hook-protected); variables documented in `docs/environments.md` | Same as AGO-143 |
| Independent review | Own security-lens pass only; independent review is left to `/pr-gate` | Brief forbids helper agents |

## Known limitations
- AC1 is proven with a mock Sentry transport (the event carries the `run_id` tag). A live event to a real Sentry project needs a DSN in `.env.local`; none was present in this worktree, so the live check is left for the tester.
- Nothing calls `tracker.captureException(error, {run_id,...})` from a run loop yet because the run loop does not exist; today the worker reports process-level fatal errors and the tracker API is ready for AGO-151+.
- Edge-runtime and server `NEXT_RUNTIME !== "nodejs"` errors are not initialised (the app has no edge routes; the proxy runs on Node).
- `NEXT_PUBLIC_SENTRY_DSN` is inlined at build time; the CSP reads it at request time. Set both at build to keep them consistent.
- The scrubber over-redacts on purpose: `token: expired` becomes `token: [redacted]`.
- The new variables are missing from `.env.example` (deny rule). **AGO-70's E2E check "`.env.example` lists every variable" fails until `NEXT_PUBLIC_SENTRY_DSN=` is added there by someone who may edit the file.** Every other E2E test passes (98 passed, 163 skipped as before; the one extra failure seen once, `ERR_NO_BUFFER_SPACE` on a chunk fetch in `csp.spec.ts`, did not reproduce and that spec passes 14/14 on rerun).

## Testing notes
- `pnpm --filter @ago/shared test`: redaction rules for every secret shape in free text, keys, cycles, whole events.
- `pnpm --filter @ago/worker test` (`sentry.test.ts`, mock transport): (a) injected error in a run context carries `run_id`/`agent_id`/`workspace_id` tags and tags do not leak to the next error; (b) GitHub, Supabase secret, OpenAI project, JWT, Bearer, URL credentials, `password`/`token` keys are absent from message, extra, context, request and breadcrumbs; (c) no DSN (undefined or empty): tracker disabled, `Sentry.isInitialized()` false, no transport call; fatal handlers report once, flush, exit 1.
- `pnpm --filter @ago/web test`: CSP includes the ingest origin only with a DSN and never the key; option builder scrubs events and breadcrumbs.
- `pnpm build` (bundle check) passes with and without a DSN set.
- E2E (`pnpm test:e2e`) re-run because the CSP changed.
