# AGO-111 - Configure lint, format, typecheck and unit test tooling

## Overview

Jira AGO-111 (US-016), Epic EP-00, Wave 1. Adds ESLint, Prettier (with the Tailwind plugin), Vitest and Testing Library across the workspace, plus a pre-commit hook. Blocked by AGO-57 (monorepo, Done). CI wiring is AGO-92, not here. Risk tier: low (tooling only; no auth, data or schema).

## Implementation details

- **Root scripts** (all via Turbo except format): `pnpm lint`, `lint:fix`, `typecheck`, `test`, `format`, `format:check`. Each package has its own `lint` (`eslint .`) and `test` (`vitest run`) script.
- **ESLint 9 flat config** (`eslint.config.mjs`, one root file): `@eslint/js` recommended, `typescript-eslint` strictTypeChecked + stylisticTypeChecked (type-aware via `projectService`), `eslint-config-next/core-web-vitals` (React, JSX a11y, and `eslint-plugin-react-hooks` 7 with the React Compiler rules: purity, refs, immutability, set-state-in-effect, ...). `no-explicit-any` is an error (CLAUDE.md invariant); `exhaustive-deps` is an error. Generated `database.types.ts` is ignored.
- **Prettier 3** (`.prettierrc.json`) with `prettier-plugin-tailwindcss` (stylesheet `apps/web/src/app/globals.css`, functions `cn`, `cva`). Root `tailwindcss@4.3.4` dev dependency lets the plugin resolve `@import "tailwindcss"` from `@ago/ui`. `.prettierignore` skips Markdown, `docs/`, `scripts/`, `.github/`, `supabase/`, lockfile and `.mcp.json` so other tickets' files are not rewritten.
- **Vitest 5** is the single runner, one config per package: jsdom + Testing Library + jest-dom for `apps/web` and `packages/ui` (setup in `src/test/setup.ts`, explicit cleanup, no globals); node environment for `packages/shared`, `apps/worker`, `packages/assets` (the latter two use `passWithNoTests` until they have specs). Sample tests: `packages/shared/src/index.test.ts`, `apps/web/src/app/page.test.tsx`, `apps/web/src/features/ui-gallery/is-ui-gallery-enabled.test.ts`, `packages/ui/src/components/Button.test.tsx`.
- **Pre-commit**: `simple-git-hooks` (installed by the `prepare` script) runs `lint-staged` (`eslint --fix --max-warnings=0` then `prettier --write` on staged code; `prettier --write` on json/css/yml). Docs/image-only commits match nothing and pass (~5 s, mostly pnpm start-up). The hook lives in the common git dir, so it is shared by every Orca worktree; it is guarded with `if [ -f node_modules/.bin/lint-staged ]` so a worktree that has not installed yet is not blocked. `--no-verify` is never needed.
- **tsconfig**: package `tsconfig.json` files now include `vitest.config.ts`; `tsconfig.build.json` of shared/assets/worker excludes `*.test.ts` so tests never reach `dist`.
- **Existing code touched** (mechanical): Prettier formatting of 9 files in `packages/ui`, `apps/web` (UiGallery), `turbo.json`, `apps/web/tsconfig.json`; four trivially fixable lint errors (void arrow shorthands, empty no-op subscribe, redundant `??`). Behaviour is unchanged: the unknown-theme fallback icon in `ThemeToggle` was kept via a typed lookup.

## Decisions taken (no human at the keyboard; recommended option chosen)

| Decision                            | Chosen                                                         | Why                                                                                            |
| ----------------------------------- | -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| ESLint major                        | 9 (flat config)                                                | `eslint-config-next` 16 and its bundled plugins target 9; 10 is newer than that ecosystem.     |
| Hook manager                        | simple-git-hooks + lint-staged                                 | Tiny, no shell shims, works on Windows and in worktrees; husky needs per-repo `core.hooksPath`. |
| One root ESLint config vs per-pkg   | One root config, per-package `lint` scripts via Turbo          | Single rule set; Turbo caches per package.                                                     |
| Existing lint errors                | Fixed (4, trivial)                                             | Instructed: fix only when trivial; none needed to be downgraded to warnings.                   |
| Prettier scope                      | Code and config only; docs, scripts, `.github` ignored         | Avoids rewriting other tickets' files and conflicts.                                           |
| React Compiler rules                | Via react-hooks 7 (bundled in `eslint-config-next`), as errors | Official compiler-compatible rule set; no separate plugin.                                     |
| `@next/next/no-html-link-for-pages` | Off                                                            | App Router only; the rule needs a `pages/` dir and only produced noise.                        |
| Test runner                         | Vitest everywhere, `globals: false`                            | Coordinator note; explicit imports keep `no-undef`/types simple.                               |

## Known limitations

- No coverage thresholds yet. `apps/worker` and `packages/assets` have no specs (`passWithNoTests`).
- `pnpm test:e2e` does not exist yet (Playwright is a separate ticket); skipped.
- The hook runs ESLint per staged file with type-aware rules, so the first run after a cold start is slower.
- Prettier does not format Markdown; ticket notes in this file are hand-wrapped.

## Testing notes

`pnpm lint && pnpm typecheck && pnpm test && pnpm format:check && pnpm build` all exit 0. Hook verified by hand: staging `export const a: any = 1;` is rejected (`no-explicit-any`); a docs-only commit passes.
