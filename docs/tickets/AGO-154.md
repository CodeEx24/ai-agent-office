## Overview

Jira AGO-154 (US-029), Epic EP-17 (Self-modification), Wave 2, WS-E Security & Governance. Only humans can change prompts, skills, policies and boot files; an agent's attempt to change them becomes a **proposal** and nothing changes. High risk: AI/prompt surface, policy and identity enforcement.

## Acceptance criteria (verbatim)

1. Given an agent tries to edit its own prompt, when submitted, then a proposal is created and nothing changes
2. The routes for those changes reject agent identities
3. Tests pass, no regressions, PR reviewed and merged, docs updated (see Definition of Done)

## Implementation details (design)

Two layers, as the repo's other guardrails (AGO-148 human-only guard, AGO-34 policy hook) are built:

1. **Worker guard** (`apps/worker/src/self-modification/`): `guardConfigChange(change, deps)` is the one gate any agent-side write to protected configuration must pass. A change names a protected target (`agent_prompt`, `skill`, `policy`, `boot_file`), the workspace, the acting agent and the proposed content. For an agent actor it never applies the change: it creates a proposal through a `ProposalStore` interface and returns `{ outcome: "proposed", proposalId }`. A store failure returns `{ outcome: "denied" }`, never an applied change (fail closed). No content is logged (only target kind and ids).
2. **Web routes and actions** (`apps/web/src/features/**`): every server action that changes a skill (create, save, assign, unassign) calls `requireHumanRequest()` first, so an agent credential is refused before any role check or write (defence in depth beside the proxy). A shared helper turns `AgentCredentialRejectedError` into the action's error state. Agent edit/duplicate/archive files are AGO-89's (parked): not touched; the same helper is ready for them.
3. **Shared types** (`packages/shared/src/self-modification/`): Zod schemas for the protected target kinds, the change request, the proposal and the guard result; a pure `classifyBootPath(path)` that says whether a path is a boot file.

Reuse: `requireHumanRequest` / `AgentCredentialRejectedError` (AGO-148), interface-plus-pg-store style (AGO-148/164), Zod at the boundary.

## Boundaries

- **Always:** scope by workspace_id; validate with Zod; agent actors only ever produce proposals; fail closed; never log proposal content.
- **Ask first:** the proposals table (schema slot), any new dependency.
- **Never:** let an agent approve its own proposal, apply a change from the agent path, edit settings, hooks or CLAUDE.md.

## API changes

No new endpoint. Skill server actions return an error state ("for people only") for an agent credential. No change for humans.

## Known limitations

- Proposals are not persisted until the follow-up table exists (Decision #1 = A): the store interface and an in-memory store are provided; the Postgres store is the follow-up.
- No vault write tool exists yet; when AGO-121 adds one it must call `guardConfigChange`.
- Review/approve UI for proposals is out of scope.
