# AGO-164 - US-032 Build the typed run event emitter

## Overview
Typed run events as Zod schemas in `packages/shared`, and an emitter in `apps/worker` that validates an event and appends it to `run_events`. Jira: AGO-164, epic EP-02 (Agent runtime), wave 2, risk tier high (audit trail, security invariants). Blocked by AGO-102 (append-only `run_events`, DB-assigned per-run `seq`) and AGO-143 (worker skeleton), both done. Blocks AGO-167 (tool loop) and AGO-40 (budgets).

Acceptance criteria:
1. Every event matches a Zod schema.
2. Sequence numbers increase without gaps within a run.
3. All events in the Master List event table are defined.
4. Tests pass, no regressions, PR reviewed and merged, docs updated.

## Implementation details
- `packages/shared/src/events/run-events.ts`: `RUN_EVENT_SCHEMAS` (one entry per event), `runEventSchema` (discriminated union on `type`, with a `version` field, currently `1`), `RunEvent`, `RunEventInput`, `toRunEventColumns`, `parseStoredRunEvent`, `isApprovalGranted`.
- `apps/worker/src/events/run-event-emitter.ts`: the `RunEventEmitter` interface (what AGO-167 depends on), the `RunEventStore` port, `createRunEventEmitter({ workspaceId, runId, store, logger? })`, and `RunEventValidationError` / `RunEventWriteError`.
- `apps/worker/src/events/pg-run-event-store.ts`: Postgres store (`pg` pool owned by the caller). It inserts **without `seq`**, so the AGO-102 trigger assigns `max + 1` under a per-run advisory lock. The emitter never invents sequence numbers and relies on the database for concurrency.
- Storage mapping: `type` column = event type; `payload` column = `{ version, ...fields }`. `workspace_id` and `run_id` are bound by the emitter, not part of the event.
- Safety: every payload schema is `.strict()` (unknown keys rejected, so a stray secret field cannot ride along); tool inputs and outputs travel as sha256 hashes, never raw values; free text is length-bounded; validation errors and logs carry paths and messages only, never the offending values; the logger only gets event type and seq.

### Event list (v1)
The Master List event table was **not found** (not in the repo, Jira text search found no table, Confluence search returned 404; Rovo search was deliberately not used because it can bill credits). The coordinator approved this list, derived from the epics, as the **v1 source of truth**. It is amendable in one file: add or edit one entry in `RUN_EVENT_SCHEMAS`.

| Group | Types |
|---|---|
| Run lifecycle | `run.created`, `run.started`, `run.completed`, `run.failed`, `run.paused`, `run.resumed`, `run.stopped`, `run.limit_reached`, `run.loop_detected` |
| Steps | `step.started`, `step.completed` |
| Tool calls | `tool_call.requested`, `tool_call.started`, `tool_call.completed`, `tool_call.failed` |
| Policy | `policy.decision` (allow / deny / needs_approval) |
| Approvals | `approval.requested` (carries `payload_hash`), `approval.decided` (approved / denied / expired) |
| Budget | `budget.usage`, `budget.exceeded` |
| Handoffs | `handoff.created`, `handoff.accepted` |
| Errors and output | `error.raised`, `message.emitted` |

Approval rules encoded in the schema: `approval.decided` with outcome `expired` is a **deny** (timeout means deny; `isApprovalGranted` is true only for `approved`) and must be `decided_by: "timeout"`; `approved` and `denied` must be `decided_by: "human"`, so an event can never record an agent or a timeout approving. `run.resumed` only allows `resumed_by: "human"`.

### Decisions taken (recommended option chosen, no human available)
- **Master List missing: use the coordinator-approved v1 list** (two tweaks from the coordinator: expiry documented as a deny; `payload_hash` on `approval.requested`, also kept on `approval.decided`).
- **Version inside the stored payload, not a new column.** No migration, no schema slot needed.
- **Emitter bound to one workspace and run**, store behind an interface (vendors/DB behind interfaces; tool loop can use a fake).
- **Strict payloads and hashes instead of raw tool I/O.** Keeps secrets and full payloads out of the append-only log.
- **No actor column** (AGO-102 follow-up): `decided_by`, `requested_by` and similar live in the payload where the decision matters.
- **Concurrency is the database's job**: no in-process counter or lock, so several emitters (or worker instances) per run stay correct.

## Known limitations
- Master List not found; the v1 list may need amending when it is located (one file).
- Free-text fields (`message`, `summary`, `reason`) are bounded but not scanned for secrets; callers must not put secrets in them. Tool arguments and results must be passed as hashes.
- Concurrent emits in one run get seq in database commit order, not call order; callers that need order must await each emit.
- The emitter does not retry; a failed write raises `RunEventWriteError` and the caller decides.
- Stored events written before this ticket (type `test` and similar) do not parse; `parseStoredRunEvent` returns `null` for them.
