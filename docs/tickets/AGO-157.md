## Overview

Jira: AGO-157 (US-030), Epic EP-17 (Identity), Wave 2 (Agent Runtime + Guardrails), WS-E Security & Governance.

Keep secrets on the server so agents and models never see key values; tools call the broker with a reference (`secret:<name>`). A tool that needs a key asks the broker to run a function with the value; the value never reaches the model, the run events or the logs, and every broker call is logged with the agent and tool.

Acceptance criteria (verbatim from the ticket):

1. A test prompt asking for a key returns no value
2. Secrets never appear in prompts, run events or logs
3. Broker calls are logged with the agent and tool
4. Tests pass, no regressions, PR reviewed and merged, docs updated (see Definition of Done)

Assumptions (source): a "reference" is a name, not a value (ticket); the agent credential from AGO-148 is the proof the agent holds a capability (code); the policy engine still decides every tool call and the broker never approves anything (CLAUDE.md invariant); no migration is needed, because the value store is an interface (guess, see Decisions).

## Implementation details

| Piece | Where | Role |
|---|---|---|
| Secret reference + audit shapes | `packages/shared/src/credentials/broker-schemas.ts` | `secretRefSchema` (`secret:<name>`), `BROKER_OUTCOMES`, audit entry type. Pure, no `node:crypto`, client-safe |
| Value store seam | `apps/worker/src/credentials/secret-store.ts` | `SecretStore` (resolve by workspace + name, with the capabilities the secret may serve) and an in-memory implementation |
| Scrubber | `apps/worker/src/credentials/secret-scrubber.ts` | Removes the exact value and its base64, base64url, hex and URL-encoded forms from any text, then applies the shared `scrubString` |
| Broker | `apps/worker/src/credentials/credential-broker.ts` | `createCredentialBroker`: verify the agent credential (AGO-148 verifier), check the secret is allowed for the capability, run the caller's function with the value, scrub the result and any error, audit every outcome |
| Brokered tool helper | `apps/worker/src/credentials/brokered-tool.ts` | `createBrokeredTool`: builds an `AgentTool` whose input carries a secret reference, never a value; execute goes through the broker |
| Audit | same module | `BrokerAuditSink` + pino line: agent, workspace, run, tool, capability, secret reference (name only), outcome, reason code. Never a value, token or the tool's input |

Flow: the model sees only the tool definition and calls it with `secret_ref: "secret:crm_api_key"` and its own arguments. The loop runs the policy hook first (unchanged). The tool's `execute` hands the reference, the run's agent credential and its function to the broker. The broker checks the credential for the tool's capability, resolves the value from the store (workspace scoped, capability scoped), calls the function with the value, scrubs the returned text and any thrown message, writes one audit entry, and returns text only. There is no broker method that returns a secret value to the caller: the value exists only inside the callback, and the callback's result is text that is scrubbed.

Patterns reused: AGO-148 verifier and `CredentialRejectionReason`, AGO-104 `scrubString`/`scrubValue`, AGO-167 `AgentTool` and `ToolContext`, AGO-143 logger with context.

## Boundaries
- **Always:** scope every lookup by `workspace_id`; verify the credential before resolving a value; audit allowed and denied calls; scrub results and errors; validate references with Zod.
- **Ask first:** a migration (needs the schema slot), a run-event type, a new dependency.
- **Never:** return, log, emit or put a secret value in a prompt; let the broker approve or skip the policy check; log a tool's input; put a real-looking key in a test (fakes are built at runtime).

## API changes
None. No endpoint, no route. Worker-internal interfaces only.

## Database changes
None. The value store is an interface; the DB-backed vault (and its UI) is AGO-185.

## Dependencies on other tickets
AGO-148 (credential verifier, token redaction pattern), AGO-70 (server-only signing secret), AGO-104 (scrubber), AGO-167 (tool loop: `AgentTool`). Wiring the broker into the production tool registry and the run's credential lifecycle belongs to the ticket that adds the first secret-using tool.

## Known limitations
- No production value store yet: the in-memory store is used by tests and by whoever wires the first tool. A DB-backed vault with encryption at rest comes with AGO-185.
- A tool function that deliberately transforms the value (for example hashes it, then returns it) can defeat value-matching scrubbing. The function receives the value only for outbound calls, the shared pattern scrubber still runs, and the policy engine and tool review apply.
- No run event per broker call (see Decisions 2); the audit is a log line plus a sink.

## Testing notes
Unit tests (`pnpm --filter @ago/worker test`): reference parsing, store scoping, scrubber (plain, base64, base64url, hex, url-encoded, nested objects, regex-special characters), broker (allowed, wrong capability, revoked or expired credential, unknown or foreign-workspace secret, throwing function, audit content, denied calls audited), and an end-to-end test of the real agent loop with a fake model provider that asks for a key: the transcript, tool definitions, run events and captured log output are all searched for the value and its encoded forms. Fake secrets are built at runtime. No DB, no network, no paid calls.
